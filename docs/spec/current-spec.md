## v1.4.0（Phase 9）での変更

- 今やる一手は、今日の3件に入っている未完了の次の一手を優先する（§8）。今やる一手と今日の3件は、同じ単一のTimerから実行中表示を導く（§10、§14）。
- サイドバー・拡大タイマー・ミニに行動文を表示する。待機中のミニは見出し・状態・案内だけにする。大・特大でも勝利条件を標準より小さくしない。

- メイン画面・ダイアログ・設定・記録の細部（件数表示、操作名の使い分け、空グループの案内、英語小見出し、ミニタイマーの表記など）を整えた。各項の「P9-xx」が対応するStageを示す。
- config schema、データ形式、セッション記録の書き込み内容は変えていない。

## v1.3.2でのメイン画面表示

- 設定の基本・表示でメイン表示サイズを標準・大・特大から選ぶ。既存設定に値がない場合は標準として扱う。config schemaは3のまま。
- 拡大対象はメイン画面の本文、カード、操作部、広い画面の上部メニューである。上部メニューは、メイン画面と記録画面で同じ大きさ・位置・文字の大きさにする(設定の表示サイズに合わせる。画面を行き来しても変わらない)。記録画面の本文、サイドバー、辞書、手順書ビューアー、ミニ画面は従来寸法を保つ(P95-01)。

## P8.10での変更

- 満了ダイアログ「終わる」から不要な停止アイコンを外した。今やる一手だけの完了は結果を保持し、「次の一手を見る」を押した時点で次候補を選ぶ。今日の3件にも対応する完了は今日の3件の表示を優先する。

- 今日の実行の分数は見出し右端の「自動」と同じ軸へ揃える。サイドバーの通常Timerを`-`/`+`で変えても、操作元から意図せず次の一手へフォーカスを移さない。
- Main内の拡大Timerは実行中・一時停止中に手動で開ける。次の一手ごとの自動表示は初期値OFFで、今日の3件には採用時点の設定を保存する。Windowsの画面消灯要求は拡大表示中だけ保持し、システムスリープは抑止しない。

## 1. プロダクト概要

### 1.1 目的

Life Launcherは、迷っているユーザーに「今やる一手」を渡し、必要なアプリ・ファイル・URL・手順書とタイマーを一続きで起動するWindows向け実行支援アプリである。

予定を細かく管理することより、次の流れを短くすることを重視する。

1. 今日の方向を決める。
2. 実行可能な一手を選ぶ。
3. 必要な作業環境を開く。
4. 短時間または通常時間のタイマーを開始する。
5. 実行結果をローカルへ記録する。

### 1.2 中心となる価値

- サイドバーの少数精鋭ランチャーから、よく使う対象をすぐ開ける。
- 辞書ウィンドウから、多数の登録対象を検索して呼び出せる。
- 「今日の勝利条件」「今日の3件」「今やる一手」で判断負荷を下げる。
- プロジェクトの次の一手と作業環境を結び付けられる。
- タイマー記録から、その日の実行内容を自動生成する。
- ローカルのMarkdown、Text、HTML手順書を作業中に参照できる。
- アカウントや自前サーバーを必要とせず、データを端末内に保持する。

### 1.3 設計原則

- 実行開始までの操作数を少なくする。
- 自動確定より、ユーザーが最後に確定する余地を残す。
- 推薦は説明可能な固定ルールだけを使う。
- メイン画面は中程度の情報密度を保つ。
- 補助情報は折りたたみ、辞書、設定、別ウィンドウへ分離する。
- 黄色を意思決定とフォーカスに使い、状態色を意味別に使い分ける。
- Windowsアプリとして、マウス、キーボード、D&D、トレイを一貫して扱う。

## 2. 対応環境とウィンドウ

- 対象OSはWindows。
- メインウィンドウは初期 `1080 x 680`、最小 `860 x 560`、リサイズ可能。
- 多重起動時は新しいプロセスを増やさず、既存のメインウィンドウを復元する。

| ウィンドウ         | 用途                           | 主な特徴                                |
| ------------------ | ------------------------------ | --------------------------------------- |
| Main               | 今日の実行、記録、設定、使い方 | 閉じる操作ではトレイへ格納              |
| Dictionary         | ランチャー辞書                 | フレームレス。検索、分類、D&D           |
| Instruction Viewer | 手順書の閲覧・管理             | Markdown、Text、HTMLを表示              |
| Mini               | タイマーの小型表示             | `288 x 136`、常に手前、タスクバー非表示 |

### 2.1 トレイ

- メインの閉じるボタンでは終了せず、通知領域へ格納する。
- 実行中・一時停止中のタイマーは維持する。
- トレイアイコンの左クリックでメインを復元する。
- トレイメニューから「開く」と明示的な「終了」を選べる。

### 4.1.1 色の役割

色は「ボタンの役割」と「タイマーの種類・状態」の2つの軸で使う。同じ緑・赤でも軸が違うため、次の表で区別する。

| 色 | ボタンの役割 | タイマーの種類・状態、その他 |
| --- | --- | --- |
| 黄色(アクセント) | 今日の3件の選択入口(「今日やるものを選ぶ」、Picker内の「＋ 今日へ」)、空状態の最初の操作 | 今日の勝利条件、今日の3件の選択・挿入位置、キーボードフォーカス、実行中の時間表示 |
| 緑 | 保存・決定 | 短時間タイマー、実行中、完了、成功 |
| 青 | なし | 通常タイマー |
| 橙 | なし | 一時停止 |
| 赤 | キャンセル、削除、初期化、復元、バックアップを未設定にする | 終了、破棄 |
| 中立色 | 追加(「＋ プロジェクト」「＋ やりたいこと」、次の一手カードの「＋ 今日へ」)、編集・設定、メンテナンス操作、その他の補助操作 | 待機中、補助表示 |

- 保存・決定の緑とキャンセルの赤はオーナー指定で、変えない。
- 色は上の既存tokenだけで指定し、新しい色を作らない。
- 今やる一手の表示色はプロジェクト色で、黄色は使わない。
- 黄色のボタンとして残すものと理由:
  - 「＋ 今日やるものを選ぶ」(今日の3件の入口): 黄色は「今日の3件の選択」の色で、今日の3件へ入る入口だから。
  - 今日やるものを選ぶ画面の中の「＋ 今日へ」: その画面の主目的の操作だから。Mainの次の一手カードの「＋ 今日へ」は、次の一手を見ている途中の補助操作なので中立色にする。
  - 空状態の最初の操作(「＋ プロジェクトを設定」「＋ やりたいことを設定」など): 空状態は最初の一歩を示す黄色のCTAとする、§9の既存の定めによる。
- 追加ボタン、メンテナンスの「アイコンキャッシュ再生成」「ミニウィンドウ位置をリセット」「手順書ウィンドウ位置をリセット」は中立色にし、黄色を勝利条件、今日の3件の選択、フォーカス、実行中の時間へ集める。「バックアップから復元」と、設定 > 手順書の「解除」は、「バックアップを未設定にする」と同じ赤の扱いにする。設定の中立ボタンのhover / focus-visibleは、Mainの中立Action(枠 `--muted`、背景 `--control-neutral-hover-bg`)と同じ反応にし、キーボードフォーカスの黄色い輪は残す。
- プロジェクト色はamber、blue、green、violet、rose、cyan、orange、slate。

### 4.1.2 枠線の役割

枠線を付けるのは、次の役割の要素だけにする。まとまりは余白で、セクションは見出しの文字で区切る。

| 枠を付ける | 枠を付けない(Main) |
| --- | --- |
| 今日の勝利条件、今日の3件・次の一手・やりたいこと・今日の実行の見出しバー(1px `--line`、v1.3.4と同じ。hoverは枠を `--muted`、背景を `--control-neutral-hover-bg` にする)(P9-14) | 上部メニューの外枠(`.topPills`)と、その中のボタン(hoverは背景、選択中の強調は残す) |
| カード(今やる一手の本体と左のアクセント線、今日の3件と上端のプロジェクト色の線、次の一手と左端のプロジェクト色の線) | セクションの上線(今やる一手、今日の3件、次の一手、やりたいこと、今日の実行) |
| 開始ボタン(短時間・通常・計測、今日の3件の開始)と主要な確定ボタン | (P9-14で、見出しバーは「枠を付ける」へ戻した) |
| 入力欄、ダイアログ、メニュー、トーストの外枠 | 今日の3件カード内の「手順書」「今日の3件から外す」「＋ きっかけ」、今やる一手の「他の一手」「手順書」(枠なしのテキストボタン) |
| 「今日やるものを選ぶ」の外側の点線 | 「今日やるものを選ぶ」の内側の面 |

- 枠をなくす要素は、枠の太さを残したまま透明にし、見た目の箱・押せる範囲・配置を変えない。
- 枠をなくしたボタンも、hoverは背景(`--control-neutral-hover-bg`)で示し、`:focus-visible`は黄色い輪(`--accent-strong`、2px)で示す。見出しバーは、内側の開閉ボタンにフォーカスがあるときバー全体に輪を出し、このとき開閉ボタン自身には輪・枠・背景を出さない(四角が二重にならない)。見出しの中の別のボタン(「＋ プロジェクト」「＋ やりたいこと」「…」)にフォーカスがあるときは、そのボタンの輪だけを出し、バー全体の輪は出さない(P9-14)。
- サイドバー、ダイアログの中身、記録画面、設定画面は対象外で、従来どおり。

### 4.2 Main本文のAction

- Main本文と記録画面の明示的なAction buttonだけに、共通のhover、keyboard focus、pressed feedbackを適用する。
- 今日の3件の選択入口と空状態の最初の操作はgold、追加・編集・設定・非破壊操作はneutral、今日への採用・復元はpositiveを使う(色の役割は§4.1.1)。Timerのgreen / blue / neutral、破壊操作のred、statusとプロジェクト色は既存semanticを維持する。
- hoverとkeyboard focusは背景と境界を強め、`translateY(-1px)`と控えめなshadowを120msで表示する。pressedは`translateY(0) scale(.985)`へ戻し、buttonのレイアウト寸法は変えない。
- `prefers-reduced-motion`では色とfocus feedbackを残し、移動・拡縮とtransform transitionを止める。disabledまたは`aria-disabled`のActionは移動させない。
- 上部toolbar、sidebar、context menu、section header、status / badge、D&D surface、ellipsis / icon control、Timer controlは共通Action hoverの対象外とする。

### 4.3 文字と形状

- 基本フォントは `Segoe UI`, `Yu Gothic UI`, `Meiryo`, `system-ui`, `sans-serif`。
- 標準表示ではページタイトル約22px、勝利条件・今やる一手約17px、見出し・本文約14px、補足約11px。大・特大ではメイン画面の本文と上部メニュー(記録画面でも同じ)を段階的に拡大する。勝利条件(表示・編集とも)は今やる一手の行動文と同じく、標準17px・大19px・特大20px で、標準より小さくならない。
- 文字間隔は0を基準とし、負のletter-spacingは使わない。
- 基本角丸は `8px`。
- セクション全体を装飾カード化せず、カードは個別項目と操作面に限定する。
- 長いラベルは省略表示とツールチップで補完する。
- ボタン、カード、ツールバーには安定した寸法を与える。
- ダイアログの上に英語の小見出し(eyebrow)、下に日本語の見出しを置く形は、全ダイアログ共通の作りとして残す。同じ対象には同じ英語を使う(やりたいこと=`Wishlist`、辞書=`Dictionary`)(P9-10)。
- ダイアログの操作行で、保存・追加・決定などの緑のボタンとキャンセルの赤いボタンは、文字の大きさと太さをそろえる(色は変えない)。`.dialogActions`・辞書の設定・手順書の未保存確認の操作行は12px、今日やるものを選ぶ画面は11px(P9-10)。

## 5. 左サイドバー

### 5.1 ブランドと辞書

- 左上にカラーアイコン、`Life Launcher`、`Quick`を表示する。
- 上部に検索アイコン付きの「辞書を開く」と、設定中の辞書ショートカットを表示する。未設定ならバッジは表示せず、登録失敗中は警告状態を示す。
- `Life Launcher / Quick`横には設定中のMainショートカットを表示する。長いキー表記は省略し、ツールチップには全文を示す。
- クリックまたは設定済みショートカットで辞書を開く。

### 5.2 Quickグループとボタン

- `showInSidebar=true` のランチャーだけを表示する。
- グループは折りたたみでき、状態をローカルに保持する。
- 見出しには名称と項目数を表示する。
- グループの右クリックから追加、名称変更、削除を行う。
- グループはD&Dで並べ替えられる。
- ボタンはアイコンとラベルを表示し、クリックまたはフォーカス後のEnter / Spaceでアクションを定義順に実行する。
- グループ見出しはクリックまたはフォーカス後のEnter / Spaceで折りたたみ、`aria-expanded`で状態を公開する。
- ボタンの右クリックから編集、対応するローカル対象のExplorer表示、辞書に移動、削除を行う。辞書に移動しても登録内容とアクションは保持する。
- Explorer表示は単一のlocal file / folder actionだけを対象とし、URL、shell-special、複数actionでは表示しない。
- ボタンは同一グループ内および別グループへD&D移動できる。
- 約6pxの開始しきい値で通常クリックとの誤判定を避ける。
- ドラッグ対象にはゴースト、移動先には黄色の挿入線を表示する。
- ドラッグ中以外は挿入線を表示しない。
- 初期configは特定用途のサンプルを持たない汎用的な空状態。
- サイドバーに表示するボタンが0件のグループも表示する(CHANGELOG「空のグループも表示できるようにした」)。0件のグループを開いたときは、見出しの下に控えめな文「見出しを右クリックしてボタンを追加」を表示する(P9-09)。この行はグループの一部で、ボタンのD&Dの移動先として従来どおり働き、見出しの見た目は変えない。折りたたんだグループには出さない。

### 5.3 サイドバータイマー

- 待機中は通常タイマーの分数を表示する。待機中だけ分数(34px)を中立色(`--text-muted-readable`)にし、実行中の黄色・一時停止中の警告色は変えない。「通常タイマー」の文字は上の見出しの1回だけで、分数入力の上には出さない(入力グループの `aria-label="通常タイマーの分数"` は残す)(P9-09)。
- `-` / `+` は5分単位、数値入力とスピナーは直接変更。
- 分数表示の上下ドラッグは1分単位。
- 設定範囲は1〜240分。
- 実行中は対象名、残り時間、進捗、一時停止、終了を表示する。
- 一時停止中は再開と終了を表示する。
- 実行中・一時停止中は拡大ボタンを表示する。待機中は表示しない。

## 6. 上部ヘッダー

- メイン画面のタイトルは `今日 ・ N分`、隣に月日と曜日を表示する。
- 記録画面では「記録」に切り替える。
- 意味が曖昧だった「通常」バッジは表示しない。

| グループ | 日本語        | 英語           | 役割             |
| -------- | ------------- | -------------- | ---------------- |
| System   | 自動起動      | Startup        | Windows自動起動  |
| System   | ミニ          | Mini           | ミニタイマー     |
| View     | 記録 / メイン | Records / Home | 画面切替         |
| View     | 手順書        | Instructions   | 手順書ビューアー |
| Help     | 使い方        | Guide          | アプリ内ガイド   |
| Help     | 設定          | Settings       | 設定ダイアログ   |

- アイコンと短い名称を併記する。
- 日本語または英語は実行環境の言語に合わせる。
- ホバー時は背景、境界、文字色を変える。
- 自動起動が有効な場合は緑の状態表現を維持する。
- 狭い幅ではラベルを段階的に隠し、アイコン、ツールチップ、ARIAラベルは残す。

## 7. 今日の勝利条件

- 今日もっとも達成したい状態を1件だけ表示する。
- 金色の枠とトロフィーで優先度を示す。
- チェックボックスで達成状態を切り替える。
- 本文はインライン編集でき、最大90文字。
- 候補チップは入力欄へのセットまでとし、自動確定しない。

## 8. 今やる一手

- 説明可能な固定ルールで1件を提示する。
- 次の一手がある全Projectを候補とし、今日の3件への採用、今週の重点、当日のセッション有無、全履歴で最後に実行した日時、手動順序を材料にする。今週の重点は優先順位を上げるが、候補を限定するfilterにはしない。
- 並び順は次のとおり。0. 今日の3件に、そのProjectの今の次の一手と同じ世代の未完了項目がある(ある方が先)。1. 今週の重点。2. 当日のセッション無し。3. 最後の実行が古い。4. 手動順序。条件0はfilterではなく、今日の3件に対応しないProjectも後ろに残り、「他の一手」で選べる。
- 条件0は、`today.date`が今日と一致し、項目が未完了で、`sourceKey`が`project:<projectId>`、`sourceGenerationId`と`nextStep.generationId`が厳密一致(両方なしは一致、片方だけは不一致。§14と同じ)のとき成立する。手動追加、やりたいこと由来、完了済みの項目は対象外。対応する候補が複数あるときは、その中を条件1〜4の順に並べる。今日の3件が0件、または全件完了の日は条件0を使わない。
- 並び替えはRust(`build_do_now_candidates`)で行い、理由コード`today3`(条件0で先頭グループに入った候補)を返す。
- 推薦理由を短い補足として表示する。`today3`は「今日の3件に入っている一手です」。14日以上空いた場合の短時間案内が最優先、「他の一手」で切り替えた候補は「今の状況から選んだ別の候補です」のままとする。今日の3件を追加・外す・完了・並べ替えたときは今やる一手の候補を読み直す。
- 「他の一手」で選んだ候補は、番号ではなくプロジェクトIDで保持する。候補が更新されて並び順が変わっても、選んだプロジェクトが候補に残っていれば、その新しい位置に合わせて同じプロジェクトを表示し続ける(先頭に来た場合は先頭の候補として表示する)。残っていなければ先頭の候補へ戻り、あとで候補に戻っても選び直されない。「他の一手」を選んでいない間は、先頭の候補を表示し、並び順の変化に従う。「他の一手」の巡回は、表示中のプロジェクトの次の候補へ進み、最後の次は先頭(選択なし)へ戻る。
- AI、利用回数順、非公開スコアを使わない。
- プロジェクト色、名称、次の一手、任意の開始トリガー、通常時間を表示する。
- 行動文は左端から15px内側に置き、「今やる一手」のラベル文字開始位置に揃える。補足と開始ボタンの位置は変えない。
- 14日以上実行がない場合は短時間からの再開を案内する。
- 関連手順書がある場合だけ手順書ボタンを表示する。
- 右側上部に再生アイコン付きの「N分で始める」、通常開始の「通常 N分」、時間を決めない計測を横並びで表示する。再生アイコンは常時表示し、短時間・通常buttonのhover/focusでは下端accentだけを短く展開する。Today3はcompactな「N分」表示を維持する。
- 短時間は緑、通常は青。分数はグローバルまたはプロジェクト設定に連動する。
- 開始時は関連ランチャー、手順書、タイマーを同じ実行経路で扱う。
- 実行アクションがなくても、手順書の開始時表示があればタイマーを開始できる。
- 実行中は一時停止と終了、一時停止中は再開と終了へ切り替える。
- 開始候補が2件以上ある場合だけ、Timerの左と右クリックメニューに「他の一手」を表示する。どちらも同じ切替handlerを使う。
- 「他の一手」は現在表示する候補だけを切り替え、候補の優先順、今週の重点、Today3、永続データを変更しない。
- 実行中・一時停止中のTimerが「同じ行動」(§14)に当たるとき、今日の3件の対応する項目と同じ実行状態(「実行中」「一時停止」「計測中」のバッジ、一時停止/再開と終了)を表示する。操作は単一のTimerを操作する。実行中は「通常 N分」の代わりに残り時間(計測は経過時間)を表示する。同じ行動でない別の候補の開始操作は変えない。

### 完了フィードバック

- 保存済みの未完了から完了への遷移だけを起点に、約1秒の一時フィードバックを表示する。既存doneの読込、reload、画面復帰、編集、並べ替え、採用、除外、Undo、source自体の完了、保存失敗では発火しない。

- Today3個別完了は対象カードだけを緑のcheckと短いpopで示す。3件目で正確に3/3へ遷移した場合は個別演出より「今日の3件、完了！」の金色節目表示を優先し、既存の「次の3件を選ぶ」は演出中も操作できる。

### Today選択のUndo

- 「今日の3件から外す」のUndoは対象項目だけを元の前後関係へ戻す。「今日の候補から外す」のUndoは当日の除外を解除し、その操作でToday3も外した場合だけ同じ採用snapshotを戻す。
- Undoは最新configへ対象単位の逆差分を適用し、後から行った別項目の並べ替え、設定変更、Session、source、完了履歴を上書きしない。
- 日付変更、同sourceの再採用・再操作、sourceの編集・完了・削除、Today3満杯など復帰前提が変わった場合は安全に拒否する。Undo保存失敗時は成功扱いせず、通知上の操作を再試行できる状態に保つ。
- 当日の選択操作tokenは日付切替で破棄する。旧configで未定義の場合は空として読み込む。

### Today完了後の整理

- 明示的にTodayを完了した場合だけ、Session確定、Today3完了保存、完了Reward、登録元の整理の順で処理する。未完了の早期停止では表示しない。
- NextStep由来では完了済みTodayカードとProjectを残し、同じgenerationの現在NextStepだけを空にして完了snapshotを作る。同ProjectのWishlistがある場合だけ、Reward後に次の候補、自由入力、今は決めないを選べる。
- Wishlist由来では完了済みTodayカードを残し、元のWishlistを「完了にする」か「まだやりたい」として残すかをReward後に確認する。アプリが自動削除しない。
- source identityとoptionalなNextStep generationで判定し、本文一致を世代判定に使わない。同じ完了について再読込後にRewardや整理UIを再実行しない。
- 次の候補を選ぶ場合はWishlist→NextStep昇格と同じreset・保存・rollback契約を使う。自動補充や無言のNextStep生成は行わない。

## 11. プロジェクトと次の一手

- Projectは継続テーマの入れ物で、`id`、名称、目標、今週の重点、色だけを所有する。
- NextStepは各Projectが0〜1件所有する、迷ったときに戻る「再開地点」で、本文、始めるきっかけ、開始環境、手順書、Timer、開始時の拡大Timer自動表示（初期値OFF）、鮮度時刻、optionalな`generationId`を所有する。NextStepだけが実行を許された作業ではなく、Wishlistから別の項目をToday3へ採用しても現在のNextStepは残す。
- 見出し(次の一手)も、名前・件数・説明・右端操作の順で、名前のすぐ後ろに件数を置く。説明の文字は今日の3件の説明と同じ(P9-14)。
- 見出しの黄色い`＋ プロジェクト`からProjectを追加する。Projectの追加・編集画面にはNextStepの実行設定を混在させない。
- Projectのcontext menu最下部とProject編集画面のDanger ZoneからProjectを削除できる。未完了Today3でProject由来のNextStepまたはWishlistが使用中、または同Project由来sourceのTimerが実行中・一時停止中の場合は確認前とmutation直前の共通guardで拒否する。
- 削除確認にはProject名、現在のNextStep件数、所属Wishlist件数と「過去の実行記録は残ります」を表示する。「関連項目も削除」はProject・current NextStep・所属Wishlistだけを削除し、「残っている項目を完了扱いにして削除」は既存source completion形式へ未完了source snapshotを追加してから同じ削除を行う。Session、Today Activity、完了済みToday3、既存completion、他Project、未分類Wishlistは保持する。
- Project・NextStep・Wishlist・任意completionの変更は1回のconfig保存で確定する。保存失敗時は全体をrollbackし、部分削除やcompletionだけの残存を許さない。削除後もSession/Recordsは保存済みlabel・Project名snapshotを使用する。
- NextStep cardのProject領域、本文領域、右上の「…」は同じcontext menuを開く。順序は「プロジェクトを編集」、次の一手関連操作(「次の一手を編集」「別の行動に入れ替える」「次の一手を未設定にする」)、「プロジェクトを削除…」とする。NextStep cardのmenuには「プロジェクトを管理」を置かない(カード自身がある「次の一手」sectionを開くだけで意味がないため)。やりたいことのProjectグループ見出しのmenuには残す(P9-09)。旧Builderへの登録操作と「やりたいことを追加」は混在させない。
- NextStep未設定は警告色を使わない中立状態とし、後から設定できる。
- 新しいNextStepまたは置換では、前の開始環境、手順書、Timer overrideを自動継承しない。開始環境と手順書は空、Timerは全体設定を使用する。
- v2から保留された実行設定がある場合だけ、最初のNextStep設定時に「引き継ぐ」「破棄して全体設定を使う」を明示的に選ぶ。選択前は保存できず、キャンセル・保存失敗では保留し、保存成功後にだけ同じconfig保存で解消する。

### Today3との編集同期

- canonicalはNextStep(Project.id) / Wishlist(stable inbox.id)。Project NextStepの`sourceKey`は`project:{id}`を維持し、同じProject内の世代はoptionalな`generationId`で区別する。Today3右クリック「編集」は元editorを開く。曖昧な旧aliasや元データなしは編集不可。
- 未完了Today3が参照するcanonical sourceはSource Lock状態にする。NextStepは同一Projectかつ同一generation、Wishlistは同一stable IDだけを対象とし、本文一致ではロックしない。Today3が完了するか採用解除されると即座に解除する。
- Source Lock中のNextStepはProject名、鍵、緑の「✓ 今日の3件に設定済み」を同じ行へ順に表示し、カード右下には重複した使用中文字を置かない。登録元からの編集、完了、削除、昇格、置換、未設定化、領域間D&DをUIとhandlerの両方で拒否する。未設定NextStepや別generation、別IDのWishlistはロックしない。
- Source Lock中でもToday3カードの「編集」から開いた元editorだけは保存できる。この経路は元sourceと一致する現在のToday3 snapshotを1回のconfig保存で同時更新し、Timer実行中・一時停止中・確認中の既存guardは迂回しない。
- 明示保存時だけ、generationが一致するToday3へtext/trigger/projectId/buttonIds/instructionPath/instructionOpenOnStart/defaultTimerMinutes/shortTimerMinutes/expandTimerOnStartを再snapshotする。解除した任意値は残さない。[詳細matrix](../phase7.1/00-field-sync-matrix.md)。
- 現在のToday3のsourceKey、done、配列順、個数、date、勝利条件は保持する。完了済みの現在カードもdoneを維持して更新し、Session/今日の実行/sourceCompletionsは書き換えない。部分補充なし。
- Project編集はそのProject sourceだけ更新し、同じprojectIdを持つ別Wishlistは自動更新しない。Wishlist自身の編集保存時に関連Projectの現在の分数を解決する。
- 同sourceのrunning/paused/満了確認/早期終了確認中はUI・直接handler双方で拒否する。別source Timerは編集を妨げない。保存中は同source開始も拒否し、実行中の分数・開始環境を変更しない。
- sourceとToday3を一つのconfigとして保存し、成功後だけeditorを閉じる。失敗時は既存rollbackにより表示を戻しdraftを残す。ファイル置換のcrash atomic性と他writer競合の制約は監査文書を参照。
- Project/NextStep/Wishlist追加・編集footerは左保存、右キャンセル。初期入力focusは既存を維持。Start Environment / Instruction Pickerは左「選択」、右キャンセルで、初期focusも右。Pickerの選択は親draftのみ変更する。
- Project/SettingsのTimer入力順は短時間→通常。狭幅は同じ順で縦積み。分数の単位・継承・validation・増減操作は変更しない。
- 早期完了基準は有効なToday3短時間snapshotと5分の小さい方。整数1..240以外は5分fallback。基準以上・予定時間未満の手動終了だけ確認し、予定時間到達は満了が優先する。停止中編集後の新snapshotは次回から適用し、実行中には変えない。

- 次回すぐ再開する内容を、プロジェクト色・名称・次の一手・任意の開始トリガーを持つcompact rowで表示する。
- 今やる一手、Today3、NextStep cardはhover / keyboard focusで黄色の境界を共有する。今やる一手の切替表示は「他の一手」とし、計測buttonにも短時間・通常開始と同じ下端accent feedbackを適用する。
- このセクションには短時間・通常タイマー、完了チェック、常設編集ボタン、常設「今日へ」ボタンを置かない。
- 今日の3件への採用はToday3内のPicker、またはNextStep cardからToday3へのD&D/「＋ 今日へ」で行う。現在NextStepの`generationId`をToday snapshotの`sourceGenerationId`へcopyし、元のプロジェクトを残す。
- NextStep専用フォームは対象Project、次の一手、始めるきっかけ、開始環境、手順書、短時間/通常Timerを表示する。Project文脈から開いた場合は対象Projectを固定する。「やりたいことから選ぶ」は初期選択かつ黄色、「＋ 新しく入力」の選択色は緑を維持する。
- 新規設定・置換・Wishlist昇格はstableな新しいgenerationを作り、既存NextStepの編集はgenerationを保持する。完了、再snapshot、直接Do NowからTodayへの対応付けは同じgenerationだけを対象とする。両field欠落はlegacy同世代として扱う。
- 行はD&Dで並べ替えでき、ゴーストと挿入位置を区別する。設定済みNextStepを「やりたいこと」へdropすると、本文とProjectだけを新しいstable IDのWishlistへ戻し、そのProjectのNextStepを未設定にする。開始環境、手順書、Timer等の実行設定はWishlistへ持ち込まない。
- Wishlist項目をNextStep cardへdropすると、未設定cardではそのProjectの次の一手に設定し、設定済みcardでは置き換える。置換前の次の一手は本文とProjectだけをWishlistへ戻す。drag開始直後からNextStep領域を黄色で誘導し、「ここにドロップして次の一手を設定する」と表示する。保存は1回で行い、Today3、Session、完了履歴を変更せず、失敗時は全変更をrollbackする。
- NextStep cardではProject操作とNextStep操作を1つのmenuへ統合する。Project自体の並べ替えは従来どおりD&Dで行える。
- NextStep領域の右クリックには「完了にする」「削除」を置かない。「次の一手を未設定にする」は確認後に「やりたいことへ戻す」「削除して未設定にする」「キャンセル」から選ぶ。どちらの未設定化もProject、採用済みToday3 snapshot、Session、source completionを変更しない。
- NextStep由来のsource completionは、明示的なToday完了時にProjectを残して現在のNextStepを空にし、完了snapshotを追加する。実行中・一時停止中の同sourceに対する編集・空化はUIとhandlerで拒否し、保存失敗時はconfig更新をrollbackする。
- 編集では開始環境Pickerからサイドバー・辞書の登録を検索し、最大2件まで選べる。保存済み3件以上は切り捨てず、2件以下へ減らすまで新規追加だけを拒否する。ID配列順を起動順として保持する。
- NextStepごとの通常時間、短時間、開始メモ、手順書、開始時の手順書表示は今やる一手または今日の3件から開始する際に使う。

## 12. やりたいこと

- あとで取り組む候補の置き場で、初期状態は折りたたむ。
- 見出し補足は「他にやりたいこと。今日やるものは『今日の3件』から選べます。」。名前のすぐ後ろに件数を置き、説明の文字は今日の3件の説明と同じにする(P9-14)。
- Wishlistが0件のときは「やりたいことを設定しましょう」、補足、黄色の「＋ やりたいことを追加する」をToday3と同じ空状態grammarで表示し、追加dialogを開く。
- 各項目は後方互換な安定IDを持つ。旧データで欠けているIDは読み込み時に一度だけ補完して保存する。
- 小さな追加ボタンと件数は見出し枠内に置く。
- 展開本文には常設の追加行を置かない。見出しの追加ボタンから、本文と任意のProject所属を登録する小型ダイアログを開く。
- 登録ダイアログは初期フォーカス、Tab循環、IME変換中のEnter抑止、空入力と120文字上限、保存中の多重送信抑止を備える。
- キャンセル、Escape、外側クリックは未保存入力を破棄して起点へフォーカスを戻す。保存失敗時は入力を保持し、ダイアログ内で再試行できる。
- 項目名は今日の3件より少し抑えた濃度で可読性を保つ。
- プロジェクトごとのグループをWishlist自身の保存順で並べ、次の一手のProject表示順とは同期しない。所属のない項目は同じ独立順の「未分類」にまとめる。各グループは独立して開閉状態、件数、ページ状態を持つ。
- グループ見出しはD&Dで並べ替えられ、ゴーストと黄色挿入線を表示する。グループ順は含まれるWishlist項目のまとまりとして保存し、グループ内の項目順とProject表示順を変えない。Projectグループの右クリックから既存Project編集を開き、Project名・色の変更は同じProjectを参照する各表示へ反映する。
- 項目のD&Dと上下移動は同じプロジェクトグループ内だけで手動順序を変更し、ゴーストと黄色挿入線を表示する。別グループへのdropでは所属Projectを変更しない。
- 右クリックから次の一手にする、上へ移動、下へ移動、編集、完了にする、削除を行う。項目menuには「やりたいことを追加」を置かず、追加入口は見出しへ集約する。Wishlist自身には常設Today採用buttonを置かないが、各項目をToday3へD&Dすると黄色の追加誘導と挿入位置を表示し、Pickerの「＋ 今日へ」と同じadoption handlerで採用する。完了は項目を一覧から外してsnapshotを作り、削除はsnapshotを作らない。どちらも確認を必須とする。
- 「次の一手にする」はNextStep専用フォームで内容を確認してから確定する。未所属WishlistはProject選択を必須とし、Projectを推測しない。既存NextStepを置き換える場合は現在の本文を明示し、古い一手を「やりたいことへ戻す」「完了にする」「キャンセル」から選ぶ。
- 「やりたいことへ戻す」は古いNextStepの本文とProjectだけを新しいstable IDのWishlistとして残し、開始環境、手順書、Timer等の実行設定を持ち込まない。「完了にする」は古いNextStepのsource完了を記録する。「キャンセル」は何も変更しない。
- 昇格保存は対象ProjectのNextStep設定、選んだ旧NextStep処理、stable IDで指定したWishlist削除を1回のconfig保存で行う。Today3 snapshotとSessionは維持し、成功前にWishlistを消さず、stale source、キャンセル、保存失敗ではすべてを変更しない。
- 編集は専用ダイアログで行う。
- 「変更」という語は使わず、操作ごとに名前を分ける(P9-09)。カードのボタンと「…」メニューの「次の一手を編集」は今の次の一手を直す(世代を保つ)。「…」メニューの「別の行動に入れ替える」は別の行動へ入れ替える(新しい世代)。「別の行動に入れ替える」で開く画面と、やりたいことで既存の次の一手を置き換える画面の見出し(`aria-label` も同じ)は、どちらも「次の一手を入れ替える」。`aria-label` と `title` も同じ名前にそろえる。
- 本文、プロジェクト、開始環境、手順書、開始時の手順書表示を設定できる。開始環境はProject編集と共通の検索Pickerを使う。
- プロジェクト設定時は、次の一手と同じサイズで色と名称を表示する。Project名はsecondary colorかつfont-weight 650〜700、Task本文はprimary colorと既存weightを使って階層を分ける。
- 各項目は次の一手と同じcompact rowとし、行動文と右端の操作メニューを配置する。D&Dできることを示す専用記号は表示しない。未設定は「プロジェクトなし」と表示する。
- 両セクションの見出しは名称・件数・説明・右端操作の順とし、右端に黄色の追加ボタンと「…」メニューを置く。やりたいことの一覧に装飾の左線は表示しない。
- 次の一手・やりたいことの行は最小48px、上下余白5pxを基準にする。Today PickerのProject識別は本文と競合しないreadable muted metaとする。
- 行のホバーまたはキーボードフォーカス時に背景を強調する。次の一手は「編集」と右端の「…」操作を常時表示し、やりたいことはhover/focus時に右端操作を表示する。クリックで既存の右クリックメニューを開き、D&Dは開始しない。タッチ環境では操作を常時表示する。
- 旧Builderの候補除外・登録元復帰D&Dは表示しない。既存の候補除外データは保存互換のため保持するが、Picker候補には適用しない。
- 今日の3件への採用はPickerまたはWishlist項目のD&Dから行い、stable source identityの重複と3件上限を超えない。

## 13. 今日の実行

- 当日の実行記録から自動生成する。
- 手入力の「今日できたこと」入力欄は持たない。
- 初期状態は折りたたむ。
- 見出し補足は「タイマーで実行した内容」。名前のすぐ後ろに件数を置き、説明の文字は今日の3件の説明と同じにする(P9-14)。
- 緑の「自動」表示と件数を重ならないように表示する。
- 行には開始時刻、プロジェクト色、名称、実行名、分数を表示する。分数の右端は見出しの「自動」と共通の余白・軸へ揃え、桁数が変わっても右寄せを維持する。

### Main本文のスクロール

- Main本文のscroll surfaceはウィンドウ横幅全体を占め、中央の内容だけを最大幅へ制限する。広い画面で中央内容の左右に余白がある場合も、その余白上のwheel操作をMain本文のscrollとして扱う。
- セッションnoteを分類・タグ化しない。
- 実行記録の追加、編集、削除、復元、ホットリロード後に再計算する。
- 件数上限は設けない。

## 14. タイマー

```text
待機中
  ├─ 短時間/通常開始 → 実行中
              ├─ 一時停止 → 一時停止中
              │                ├─ 再開 → 実行中
              │                └─ 終了 → セッション確定
              ├─ 終了 → セッション確定
              └─ 満了 → 完了通知 + セッション確定
  └─ 計測開始 → 計測中
                  ├─ 一時停止 → 計測一時停止中
                  │                ├─ 再開 → 計測中
                  │                └─ 終了 → セッション確定
                  └─ 終了 → セッション確定
```

- アクティブなタイマーは常に1本だけ。
- 実行中または一時停止中に別タイマーを開始すると、古いタイマーを終了扱いで確定する。
- 古い項目の実行中・一時停止表示を解除してから新しいタイマーを開始する。
- 一時停止時間は実行分数へ含めない。一時停止と再開を素早く繰り返しても、時計(サイドバー、拡大タイマー、ミニ)は巻き戻らない。一時停止・再開の瞬間に表示の基準時刻をその操作の時刻にそろえ、1秒ごとの更新は、タイマーがある間は作り直さない(P95-01)。
- 手動終了、切り替え、満了確認での終了時にセッションを確定する。早期完了の確認待ち時間は含めない。
- 1分未満の実行は通常のセッション記録へ追加しない。
- 計測は0:00から実効経過時間を増やし、予定時間、満了、OS満了通知、15分延長、進捗率を持たない。一時停止時間は他のTimerと同じく除外する。
- 短時間・通常・計測の相互切替では、現在の1本を同じ終了処理で確定してから選んだmodeを開始する。切替前が1分未満なら記録しない。
- 満了後は15分の延長導線を持つ。
- noteは自由テキストのまま保存する。
- 通知は右下の共通Toastで表示する。通常通知は4秒、Undo操作付きは表示開始から8秒を標準とする。タイマーの開始・一時停止では通知を出さない(状態はカードや Timer の「実行中」「一時停止」の表示で示す)。記録の結果(「○○ N分を記録しました」「1分未満なので記録しませんでした」)、保存・記録の失敗、警告の通知は出す(P95-01)。
- pointerがToast内、focusがToast内、または文書が非表示のいずれかでは残り時間を停止し、全条件が解けた時点から再開する。待ち行列の時間はUndo猶予へ含めない。
- 同時表示は最大3件とし、それを超える未処理Undoは待ち行列に保持する。新しいToastがfocusを奪うことはなく、reduced-motionでは入退場と残時間railの動きを抑える。
- source、Today3、Builderの編集成功通知は保存元と実際の同期先に応じて「今日の3件にも反映しました」または「元の『次の一手』『やりたいこと』にも反映しました」と示す。
- 満了時はメインを復元し、OS通知と完了ダイアログを表示する。完了ダイアログの見出しは開始時点の行動文(`actionText`。空なら対象名)で、Projectがあるときは見出しの上に小さな色付きのProject識別(`ProjectIdentity` compact)を出す。ボタンと振る舞い(続ける・終わる・今日の分は完了)は変えない(P9-09)。

### 同じ行動と実行状態の同期

- 今やる一手と今日の3件は、単一の`activeTimer`から同じ実行状態を導く。画面ごとに別の状態を持たない。
- 「同じ行動」はTimer開始時に保存した`sourceId`・`sourceGenerationId`で判定する。判定は`src/timerSource.ts`の共通関数(`findTodayEntryForTimer`、`timerMatchesProjectNextStep`、`sameSourceGeneration`)に集約し、完了処理、動的な早期完了の確認、実行中表示が同じ関数を使う。
- 今日の3件の項目は、Timerの`sourceId`がその項目自身であるか、項目の`sourceKey`がTimerの`project:<projectId>`に一致する未完了の項目で世代IDが一致するとき実行中とする。今やる一手は、Timerの`sourceId`がそのProjectであるか、今日の3件の項目から開始されその項目が`project:<表示中のProject>`で、`nextStep.generationId`がTimerの`sourceGenerationId`と一致するとき実行中とする。
- 世代IDは厳密一致で比べる。両方ない場合は旧形式の互換として一致、片方だけある場合は不一致。手動追加の項目、やりたいこと由来の項目は今やる一手と同期しない。
- 実行中に次の一手を別の行動へ入れ替えても、新しい世代は実行中にならない。元の今日の3件の項目は実行中のままで、実行中の入れ替えはSource Lockで操作できない。

### 実行中の表示(行動文)

- サイドバー、拡大タイマー、ミニの3か所は、実行中・一時停止中・計測中に同じ並びで表示する。上: プロジェクトの小さな色付きラベル(プロジェクトがなければ出さない)。中央: 行動文。続いて状態(実行中・一時停止中・計測中)、時計。プロジェクト名を2回出さない。
- 行動文は開始時点の値を `ActiveTimer.actionText` に保持する。今日の3件から開始したときはその項目の文、今やる一手・プロジェクトの次の一手から開始したときは`nextStep.text`、それ以外または空のときは`label`。開始メモのテンプレートは行動文にしない。実行中に元の項目や次の一手を編集しても表示は変えない。
- サイドバーと拡大タイマーは2行まで、超えたら省略記号とし、`title`に全文を入れる。ミニは288×136のまま1行で省略記号と`title`にする。時計や操作ボタンと重ならない。ミニの状態通知(`mini-timer-snapshot`)は`actionText`を含み、古い通知で空のときは`label`で表示する。
- `sessions.jsonl`へ書く内容(noteを含む)は変えない。

### 14.1 拡大タイマー

- Mainの内部でSidebarと本文を覆う。独立ウィンドウやOS全画面モードにはしない。表示中も既存のアクティブTimerを共有し、別のカウントは作らない。
- 実行中・一時停止中のSidebarから手動で開ける。次の一手の「開始時にタイマーを大きく表示」は初期値OFFで、明示的な今やる一手・今日の3件の開始時だけ適用する。やりたいこと由来、復元時、Sidebar単独Timerでは自動表示しない。
- 一時停止・再開・終了ができる。Escまたは閉じる操作は表示だけを閉じてTimerを継続し、背景クリックでは閉じない。背景は操作不可とし、キーボードフォーカスを拡大表示内に保つ。
- 満了時は「時間になりました」を表示したまま既存の延長・終了ダイアログを前面へ出す。拡大表示中はMiniを開かず、閉じた後はMini設定に従う。
- Windowsのdisplay idleだけを抑止し、system sleepは抑止しない。拡大表示を閉じる、Timer終了、アプリ終了時に解除し、異常終了後は期限切れで解除する。APIが失敗してもTimerは継続する。

### 動的な早期完了

- 対象は未完了Today3に一意に対応するTimerの手動終了。短時間・通常は`elapsedSeconds >= thresholdSeconds`かつ`elapsedSeconds < activeTimer.targetMinutes * 60`、計測は`elapsedSeconds >= thresholdSeconds`で確認する。
- `thresholdSeconds = Math.min(5, validSnapshotOr5) * 60`。現在の `TodayItem.shortTimerMinutes` snapshotを使用し、Project値を直接参照しない。停止中の明示編集保存ではP71の同期契約に従いsnapshotが更新され、次回開始に適用される。
- 有効なsnapshotは整数1..240分。runtimeのmissing/null/小数/範囲外/非数値は5分fallback。既存の読込時補完は維持する。
- 短時間3分なら2:59では確認なし、3:00から対象。短時間10分でも5:00から対象。ただし予定時間到達は満了フローが優先し、予定3分のTimerが3:00になった場合は早期確認ではない。
- 一時停止時間を除いた実効経過秒を停止要求時に固定し、確認待ちは除外する。Session分数は切り捨て、1分未満は記録しない。延長後は現在の予定時間で判定する。
- タイトルは「今日の分は完了にしますか？」。左「今日の分は完了」、右「未完了のまま終了」で初期focusは右。Escape/閉じるは右と同じ、backdropでは閉じない。IME確定では送信しない。
- 左右ともSessionを保存し、左だけ対象Today3のdoneを更新する。NextStep/Wishlist本体とsource完了履歴は変更しない。
- Today直接source identityを優先する。今やる一手は対応する採用済みProject項目がある場合のみ対象。未採用・対応が曖昧な項目・Timer切替は早期確認の対象外。
- Session保存失敗では停止時点を固定した確認画面を維持し再試行できる。Today保存失敗ではToday3をrollbackし、保存済みSessionを保持する。二重回答・古いTimer handler・確認中の再開/切替はguardする。
- しきい値到達だけの自動完了、80%判定、2/3の部分補充、自動補充はしない。3件完了時の手動「次の3件を選ぶ」を維持する。

### 14.2 ミニウィンドウ

- 固定サイズ `288 x 136`、フレームレス、常に手前、タスクバー非表示。
- 自動表示時にフォーカスを奪わない。
- タイトル領域をドラッグして移動できる。
- ダブルクリックまたは拡大操作でメインへ戻る。
- 最後の位置を保存し、モニター外へ出た場合は補正する。
- 短時間・通常は残り時間と進捗を表示し、計測は「計測中」と実効経過時間を表示する。計測に架空の予定時間や進捗率を作らない。
- 待機中のミニは「タイマー」の見出し、「待機中」のバッジ、「開始ボタンから計測できます」の案内だけを表示する。時計と進捗は出さず、「待機中」の語は1回だけにする。

## 15. 辞書ウィンドウ

### 15.1 基本とロック

- `showInOverlay=true` の登録だけを表示するコマンドパレット。
- 初期 `760 x 520`、最小 `420 x 300`、フレームレス、リサイズ可能。
- 位置とサイズを保存する。開くたびにメインウィンドウがあるモニターを優先し、前回位置が同じモニター内なら維持、別モニターまたは画面外なら対象モニター中央へ移して作業領域内に補正する。
- 辞書表示中はメイン画面を暗くする。
- 閉じるボタンの左にロック切替を置き、初期状態はロック中。
- ロック中は範囲外クリックや他ウィンドウ操作で閉じず、暗転も維持する。
- ロック解除中は範囲外クリックで閉じる。
- ロック解除中でもタイトルバーのドラッグで移動できる。

### 15.2 ページ、検索、タイル

- 固定ページ「すべて」「未分類」とユーザー作成ページを表示する。
- 表示形式は「タイル」「リスト」から選び、アイコンサイズの「自動」「小」「中」「大」と独立して保存する。未保存時はタイル表示とする。
- 辞書設定は開いたままでも辞書ウィンドウ外を操作できる。保存操作は緑の決定色で示す。
- active pageは表示対象を決める状態で、背景と下端の金色lineで示す。外周の黄色outlineは使わない。
- keyboard focusはactive pageとは独立し、ページまたは項目へ黄色outlineで示す。項目からページへ移ると項目の選択表示を消すが、最後の項目はページ別に記憶する。
- ページ上でDownを押すと、そのページで最後にfocusした有効な項目へ戻る。記憶した項目が削除済みなら先頭の有効な項目へfallbackする。
- 固定ページは並べ替え対象外、ユーザーページはD&Dで左右へ移動できる。
- ラベル、グループ、ページ名、aliases、説明を検索対象にする。最近使ったもの、おすすめ、使用回数順は持たない。
- 登録数にかかわらずタイル寸法を共通化する。長いラベルは省略し、titleで全文を補完する。
- タイルは同一ページ内と別ページ間でD&D移動できる。ghostはpointerから約10pxずらし、別ページtabへ一定時間hoverするとページを切り替える。
- タイルはLeft / Rightで同じvisual row、Up / Downで最寄りのvisual rowへfocusを移す。
- 初回表示は最初のタイルへfocusする。閉じるとactive page、focus層、ページ別の最後の項目、scroll位置を記憶し、再表示時に復元する。
- 再表示時の検索語は復元せず空に戻す。検索結果は一時状態として扱う。
- 辞書windowがfocus中かつ入力・tab・button操作中でなければ、余白からもfocus中タイルの矢印移動を続けられる。
- 検索入力中の矢印キーと、メイン画面・他アプリのキー操作は奪わない。文字入力は検索欄へ送る。
- 最上段タイルのUpはactive pageへ戻り、categoryのLeft / Rightはactive pageを変えずfocusだけを移す。
- categoryはEnter / Spaceでactiveにし、Downでそのページの項目へ移動する。
- mouse hoverはkeyboard focusや記憶中の項目を書き換えない。

### 15.3 右クリック

- 移動、サイドバーに移動、編集、対応するローカル対象のExplorer表示、削除を行う。
- 「サイドバーに移動」は対象項目単位で有効状態を判定し、すでに表示中ならdisabledにする。
- サイドバーに移動しても辞書登録、アクション、辞書内の表示順を保持する。
- Sidebar側の「辞書に移動」はQuick表示だけを外し、辞書登録とアクションを保持する。
- 双方向の移動保存に失敗した場合は表示状態をrollbackする。
- 完了メッセージは約3秒で消える。
- メニューは最終位置へ即時配置し、横から滑り込まない。
- 画面端では内側へ補正する。
- `role=menu`、キーボード操作、Escape終了に対応する。
- focus中のタイルはShift+F10またはMenu keyで同じmenuを開く。

## 16. ランチャー登録と編集

### 16.1 対応アクション

1つのボタンは複数アクションを持ち、登録順に実行できる。

- アプリ、URL、フォルダー、ファイルを開く。
- スクリプトを引数付きで実行する。
- Windowsのごみ箱を開く。

URLはWindowsの既定ブラウザで開き、登録ごとのブラウザ指定は持たない。

### 16.2 外部D&D

- アプリ、フォルダー、ファイル、Windowsショートカット、URL、ごみ箱を受け付ける。
- ブラウザのタブ、アドレス、ブックマークURLも受け付ける。
- `.lnk` はリンク先を解決する。
- Chromeブックマークは、利用可能な場合にアクティブプロファイルから名称を得る。
- 複数項目は先頭を登録候補にする。
- ドロップだけで起動せず、確認ダイアログを経て保存する。
- 確認画面ではラベル、グループ、サイドバー、辞書、辞書ページを選ぶ。
- ごみ箱などのWindows特殊項目も内部prefixを見せず、対象名をそのまま表示する。
- 確認画面を開いた時点では完了Toastを出さず、保存完了後だけ結果を通知する。

### 16.3 アイコン

- ローカル対象はWindows Shell由来のアイコンを非同期取得する。
- ショートカット矢印を合成せず、リンク先アイコンを優先する。
- URLは対象ページまたは `/favicon.ico` から非同期取得する。
- 第三者favicon APIは使わない。
- 失敗時はUIを停止せず、種別フォールバックを使う。
- メンテナンスからキャッシュを再生成できる。

## 17. 手順書ビューアー

### 17.1 ウィンドウと左ペイン

- 初期 `960 x 680`、最小 `720 x 480`、リサイズ可能。
- 状態を保存し、モニター外を補正する。
- 常に手前は既定で有効。
- 自動表示時はフォーカスを奪わない。
- 閉じる操作は手順書ウィンドウだけを破棄する。
- toolbarのPinと再読み込みの間にサイズ切替を置き、`760 x 540`、`960 x 680`、`1280 x 840`の順に循環する。現在の中心位置を可能な範囲で維持し、DPIとモニター作業領域に合わせて補正する。
- サイズ切替は文書、選択、編集Draft、可能な範囲のscroll位置を保持し、左ペイン幅だけを初期値へ戻す。
- 左ペインは初期約248pxで、境界をドラッグまたはキーボード操作して調整できる。最小180px、最大は440px・全体の45%・本文幅320px確保のうち最も狭い値とする。
- 左ペインが狭い場合は検索の下へ「読み込み」と更新を折り返し、操作が欠けないようにする。
- 検索欄は「検索」、ほかに「読み込み」と更新を置く。
- 上部の常設「新規」ボタンは表示しない。
- 読み込みルートは最大5件で、再起動後も保持する。
- フォルダー名変更時は保存した識別情報から可能な範囲で追跡する。
- フォルダー選択ダイアログは完了まで前面に保持する。

### 17.2 対応形式

| 形式     | 表示                 | 編集             | アイコン色   |
| -------- | -------------------- | ---------------- | ------------ |
| Markdown | サニタイズ済みHTML   | プレーンテキスト | 黄系Book     |
| Text     | 改行保持テキスト     | プレーンテキスト | 青系FileText |
| HTML     | サンドボックスiframe | 読み取り専用     | 橙系FileCode |
| Folder   | ツリー階層           | 管理操作         | フォルダー色 |

- HTMLは元の文書構造、インラインCSS、相対stylesheet・画像・fontを保持したサニタイズ済み `srcDoc` を使う。
- 相対assetは検証済みの登録ルート内だけを元HTMLの親フォルダー基準で解決する。
- iframeは `sandbox="allow-same-origin"` と専用CSPで分離する。`allow-scripts`、`allow-forms`、`allow-popups`は付与しない。
- script、event handler、form controls、入れ子iframe、object、embedを除去し、リモートCSS・画像・font・通信を拒否する。
- HTML iframeは本文領域の全幅をviewportとして使い、元HTMLのresponsive layoutを反映する。
- HTTP/HTTPSリンクは外部ブラウザで開く。

### 17.3 ツリーと編集安全性

- 任意の深さの階層を表示する。
- 同一親内でD&D表示順を変更し、ローカルに保持する。
- ファイルとフォルダーの右クリックメニューを持ち、登録ルート単位の「登録を解除」を提供する。
- ファイルの「エクスプローラーで表示」は含有フォルダーを開く。
- 手順書ビューアーからPC上のファイルやフォルダーを削除しない。登録解除時は確認し、対象ルートを一覧から外すだけとする。
- キーボード操作とARIA tree semanticsに対応する。
- MarkdownとTextは明示的に編集開始し、保存または破棄する。
- 保存は一時ファイルと置換によるアトミック経路。
- mtime競合を検出し、外部変更を約2.5秒間隔で確認する。
- 登録ルート外、UNC、パストラバーサル、危険なリンク構造を拒否する。
- プロジェクト、次の一手、やりたいことへ手順書を紐づけられる。

## 18. 記録ビュー

記録画面は役割を混ぜず、次の3タブに分ける。初期表示は「ふりかえり」。メイン画面へは上部メニューの `← メイン` で戻る。タブ列の左には戻るボタンを置かない。上部メニューは記録画面をスクロールしても見え続ける(P9-10)。

記録画面の見出しの右側に文字がある所(プロジェクト別〈今週〉の日付、プロジェクト別累計の「すべての記録」、完了した項目の件数、今週の重点の n/3)は、すぐ下の枠の中の余白だけ内側に寄せ、右の文字の右端を枠の中の右端の文字とそろえる(枠のあるリストは枠の線 1px + 12px、完了した項目の行と今週の重点のチップはそれぞれの行・チップの余白)。見出しの左側、右側に文字のない見出し、右側がボタンの見出し(「最近の実行記録」)は変えない(P95-01)。

### 18.1 ふりかえり

- 今日と今週の合計時間、活動日数を表示する。
- プロジェクト別に「今週」と「累計」の履歴をaccordionで開閉する。各accordionの開閉状態は独立する。
- 今週は対象期間の実施日、実行内容、分数、回数を表示する。
- 累計は保存済みの実行内容を新しい順に5件ずつ表示し、プロジェクトごとに独立してpageを管理する。
- 実行内容は各Sessionに保存されたsnapshotだけを表示する。現在の次の一手やプロジェクト名から過去内容を推測・上書きしない。
- 保存内容が空の場合は `実行内容の記録なし` と表示する。

### 18.2 今週を決める

- 前週の合計、活動日数、プロジェクト別時間、実行記録数を事実として表示する。
- 動かしたプロジェクト、今週の重点、鮮度レビュー、明示的に完了した項目を確認する。
- 「完了した項目」は「完了にする」で候補から外した次の一手・やりたいことのimmutable snapshotであり、Today3完了やTimer Sessionとは別履歴とする。
- ランキング、前週比評価、達成率、ストリーク、グラフは表示しない。

### 18.3 すべての記録

- 実行記録を今日、今週、全期間、プロジェクト、テキストで絞り込む。
- compact rowで表示し、長い本文はellipsisとtitleで補完する。
- rowの右クリック、「…」、Shift+F10は同じcontext menuを開く。
- 実行記録を手動追加、編集、削除できる。追加・編集dialogは左に保存、右にmuted redのキャンセルを配置する。
- 以前のメモは互換表示し、初期状態では折りたたむ。他の折りたたみと同じ開閉の矢印を付け、見出しに日数を全角かっこで出す(例:「以前のメモ（3日）」。0日のときは日数を出さない)。中身がないときの「以前のメモはありません。」は変えない(P9-10)。
- noteは自由textのまま扱い、tag抽出、分類、集計を行わない。
- 今日の活動ログをclipboardへ出力でき、合計、プロジェクト別・項目別分数、時刻、作業名、noteを含める。
- 外部serviceへ自動送信しない。

| ミニタイマーを使う | ON  | チェック。`settings.miniMode`。OFFのときは上部メニューの「ミニ」ボタンとミニ切替ショートカットでミニを開けず(上部メニューのボタンの `title` とショートカットのトーストは「設定で「ミニタイマーを使う」をオンにしてください」)、開いているミニウィンドウは閉じる。ほかの用途はない |
| メイン表示サイズ | 標準   | 標準・大・特大                 |
| 今週の重点      | 未設定 | 最大3件                      |

| ショートカット | 既定値           |
| -------------- | ---------------- |
| メイン画面     | `Ctrl+Alt+Space` |
| 辞書           | `Ctrl+K`         |
| ミニタイマー切替 | 未設定         |
| 手順書         | 未設定           |

- 入力欄が未設定のときは「未設定」を入力欄の中だけに表示し、下の補足行は出さない。補足行は、記録中の案内、登録済み(「登録済み(保存時に再登録)」)、形式エラー、競合、OS予約キーのときだけ表示する(P9-10)。補足行の有無にかかわらず、同じ行の入力欄の上端はそろえる(欄の内側は上詰めで、行の高さに合わせて伸ばさない)。
- 画面に出る名前は「ミニタイマー」にそろえる(ショートカットのラベル「ミニタイマー切替」、上部メニューの「ミニ」ボタンの `aria-label`「ミニタイマーへ切り替え」と `title`、開けないときのトースト)。設定のキー `miniMode` と保存形式は変えない。
- ショートカットは登録ボタンを押した後のキー入力を記録する。
- 記録中は既存ショートカットを一時解除する。
- 重複や使用中キーを検証し、警告する。
- 登録失敗で設定全体の読み込みを失敗させない。
- 保存完了まで本登録しない。
- ショートカット以外の設定保存では登録をやり直さず、Rust側も同じキーへの再登録を避ける。実際にキーを変更した場合だけ更新する。
- 未保存で閉じる場合は確認ダイアログを出す。
- 「編集を続ける」と「破棄して閉じる」は同じ文字サイズと高さにする。

### 19.1 バックアップとメンテナンス

- バックアップ先と保持数を設定でき、既定保持数は30。
- 設定済みの場合、1日1回 `config.json`、`sessions.jsonl`、`notes.json`、`config.schema.json` と安全なPNGアイコンキャッシュをZIP保存する。復元ZIPにアイコンが含まれる場合はキャッシュを置き換え、旧ZIPに含まれない場合は現在のキャッシュを保持する。
- ZIPを選択して復元し、復元前に現在データを退避する。
- ZIPの名前、エントリー、サイズ、圧縮形式、チェックサムを検証する。
- 設定フッターは左に緑の「保存」、右に控えめな赤の「キャンセル」を置く。保存可否と未保存確認の既存契約は維持する。
- 手順書、バックアップ、メンテナンス内の黄色actionと灰色neutral actionは、hover / keyboard focus時に緑を使わず黄色の境界・背景・文字へ統一する。
- メンテナンスタブの先頭に1行「このタブの操作は押すとすぐ実行されます。保存は不要です。」を表示する。下部の「保存 / キャンセル」は他のタブと共通のため残す(P9-10)。
- メンテナンスは「データ・フォルダ」「表示・キャッシュ」「手順書」「初期化」に分類する。
- 「データ・フォルダ」から今日の活動ログをコピーし、configフォルダとバックアップフォルダを開ける。
- 「表示・キャッシュ」からアイコンキャッシュ、ミニウィンドウ位置、手順書ウィンドウ位置を管理する。
- 「手順書」から手順書一覧を再読み込みできる。
- 「初期化」は他の操作から分離して最下部へ置き、赤い「ソフトウェアリセット...」を入口にする。

### 19.2 ソフトウェアリセット

- ソフトウェアリセットは、バックアップ選択と最終確認の二段階で実行する。最終確認は安全側の操作へ初期focusを置く。
- 実行中または一時停止中のTimer、完了確認、早期終了確認がある場合は開始せず、Timerを終了してから実行するよう案内する。
- 最初の段階で、現在データを検証済みZIPへ保存して続けるか、ユーザー向けZIPを作らず続けるかを選べる。どちらを選んでもrollback用の内部snapshotは省略しない。
- reset対象はLife Launcherが所有するconfig、Session、互換notes、schema、icon cache、既知のUI保存状態、window state、autostart登録とする。config内のQuick、辞書、Project、NextStep、Wishlist、Today3、勝利条件、完了履歴、設定も初期状態へ戻る。
- 登録先のアプリ、ファイル、フォルダー、URL、手順書本体と周辺asset、ユーザー指定backup folder、既存backupは削除・移動しない。登録情報だけを初期化する。
- frontendはapp-owned localStorageをcaptureしてからclearし、backend commandが検出可能な失敗を返した場合はcaptureから復元する。
- backendはcommand受領後に内部snapshotとdurable journalを保存してからruntime file、icon、window state、autostartを変更し、検出した途中失敗ではsnapshotからrollbackする。
- 起動時は通常のconfig読み込みより前に未完了journalを確認する。中断された処理はsnapshotから復旧し、frontendがlocalStorage復旧を適用してacknowledgeするまで復旧情報を保持する。
- 成功時は補助windowを閉じてprocess restartを要求する。再起動後はProject 0件を含むcanonical初回起動状態から使用できる。
- 詳細な境界と失敗時契約は [ソフトウェアリセット](../phase8.3/software-reset.md) に定める。

## 22. データと日付

| ファイル / フォルダー | 用途                                                                         |
| --------------------- | ---------------------------------------------------------------------------- |
| `config.json`         | ランチャー、プロジェクト、今日、当日の候補除外、やりたいこと、完了項目、設定 |
| `config.schema.json`  | configのJSON Schema                                                          |
| `sessions.jsonl`      | タイマーと手動追加の実行記録                                                 |
| `notes.json`          | 旧形式互換データ                                                             |
| `icons/`              | アイコンキャッシュ                                                           |
| `backups/`            | 更新前退避                                                                   |

- configの現行データ版は `3`。v2移行は専用decoderとv3全体検証を通し、変換前raw backupの作成成功後にだけ一時ファイルとWindowsの原子的置換で書き込む。失敗時は`changed: false`、`saveBlocked: true`として元ファイルを書き換えず、future versionも拒否する。未リリースv3内で追加したoptional generation fieldはversionや`sourceKey`を変えず、v2 NextStepと既存Today3には遡及付与しない。詳細は[Phase 8.1 config v2→v3移行](../phase8.1/config-v2-to-v3-migration.md)を参照する。
- UIからのconfig書き込みはRustのアトミック保存経路へ統一する。
- 外部変更はホットリロードする。
- 既定の1日開始時刻は4時。
- `date_key_at` と `today_date` を共通の日付判定に使う。
- 開始時刻より前は前日扱い。
- 今日、セッション、記録、日次バックアップで同じ境界を共有する。
- 日付変更時は今日の項目を初期化し、未完了を自動繰り越ししない。

## 22. ネットワークと権限

### 22.1 favicon取得

- HTTP/HTTPSだけを許可し、資格情報入りURLを拒否する。
- localhost、loopback、link-local、private、特殊用途IPv4/IPv6を拒否する。
- DNS解決結果を検査し、検査した宛先へ接続を固定する。
- プロキシを介さず、リダイレクトは最大5回。
- 接続3秒、1リクエスト6秒、全体15秒のタイムアウト。
- HTML最大512KiB、画像最大2MiB、候補最大8件。
- Content-Typeを検査し、画像はデコード後に保存する。

### 22.2 Tauri capability

| ウィンドウ  | 主な許可                                                                           |
| ----------- | ---------------------------------------------------------------------------------- |
| Main        | 基本API、補助Webview、表示、フォーカス、位置・サイズ、常時手前、自動起動、状態保存 |
| Dictionary  | 基本API、非表示、フォーカス、ドラッグ、リサイズ、状態保存                          |
| Instruction | 基本API、破棄、常時手前切替                                                        |
| Mini        | 基本API、ウィンドウドラッグ                                                        |

- 補助ウィンドウへMain専用権限を付与しない。
- capability契約をRustテストで確認する。

## 23. レスポンシブ動作

- 最小幅内でサイドバーと主要操作を維持する。
- 上部ラベルを段階的に省略しても、アイコンと操作は残す。
- プロジェクトカードは自動折り返しする。
- 長い日本語・英語は省略または改行し、隣接操作へ重ならない。
- 辞書と手順書は個別の最小サイズと内部スクロールを持つ。
- ビューポート幅で文字サイズを連続拡大縮小しない。

## 24. 明示的な非目標

- カレンダー、ヒートマップ、ストリーク、達成率、ランキング、統計グラフ。
- 未完了タスクの自動繰り越し、今日の3件制限解除。
- 期限、優先度、サブタスク、一般的なタグ管理。
- アカウント、ログイン、自前サーバー、クラウド同期、スマートフォン連携。
- AI提案、自動分類、自動確定。
- 勝利条件や次の一手の自動セット。
- 辞書の最近使ったもの、おすすめ、使用回数順。
- noteのタグ抽出、分類、集計。
- URLごとのブラウザ指定。
- 活動ログの自動送信、週次重点の自動リセット。

## 25. 主要な不変条件

1. アクティブまたは一時停止中のタイマーは1本だけ。
2. 今日の3件は最大3件。
3. サジェストは入力欄へのセットまでで、確定はユーザー操作。
4. configのUI書き込みは既存のアトミック保存経路を使う。
5. 日付判定はRustの共通関数へ集約する。
6. ミニウィンドウの自動表示はフォーカスを奪わない。
7. ドロップ対象を確認なしで起動しない。
8. 手順書削除はごみ箱を使い、永久削除へ自動移行しない。
9. セッションnoteは自由テキストのまま保持する。
10. 推薦は説明可能な固定ルールだけを使う。

## 26. 現行制限

- UIは日本語中心で、英語対応は主に上部ツールバー等の一部表示。
- URLはWindowsの既定ブラウザで開く。
- favicon取得失敗時はフォールバックアイコンになる。
- Chromeブックマーク名取得はローカルプロファイルを読める場合に限る。
- HTML手順書は静的HTML/CSSと登録ルート内の相対assetを通常ブラウザに近い形で表示する。JavaScript依存UI、form、nested frame、リモートassetは安全性のため動作しない。
- 手順書フォルダー追跡はローカルドライブ上の安全なパスを前提とする。
- `notes.json` は互換目的で残るが、「今日の実行」は `sessions.jsonl` から生成する。
- アプリ内自動アップデーターは現行仕様に含まれない。

## 27. Web Demo companion

- Web Demoは別repository `Takuyakou/life-launcher-web`で管理する静的SPAであり、Windows製品版の完全移植ではない。
- Demoの中心フローは、Project NextStepまたはWishlistへ候補を登録し、候補選択画面で最大3件を選び、Today3から実行する。

- backend、認証、analytics、外部APIを使用せず、入力はブラウザのlocalStorageだけに保存する。
- Windows本体Phase 7.2との差分と将来の同期条件は [Web Demo Phase 7.2 Follow-up](../phase7.2/web-demo-followup.md) に記録する。
