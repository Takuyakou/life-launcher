## 調べた方法(使っていないクラスの見つけ方)

スクリプトは、この PR には入れていない(一時的なもの)。手順は次のとおり。

1. `postcss`(すでにある開発用の依存。新しい依存ではない)で `src/styles.css` を読み、すべての規則(`@media` の中を含む)のセレクタからクラス名を取り出した。CSS に出るクラス名は 870 個。
2. 製品のコード(`src/` の下の `.ts`・`.tsx`・`.html`・`.js`・`.json`・`.md`、つまり `src/content/` を含む。それと `index.html`)をすべてつなげて、クラス名が**単語として**出てくるか(前後が英数字・`_`・`-` でない)を調べた。出てこないもの: 81 個。
3. そのうち、動的に組み立てるクラスの接頭辞(`toast--${…}`、`confirmDialog--${…}`、`instructionFileIcon--${…}` など、`接頭辞--` の直後に `${` か `" +` が続くもの)で始まる 16 個は「使っている」として除いた。残りが **65 個**。
4. 65 個それぞれについて、コード全体に文字列として一切出てこないこと(部分一致も 0 件)と、同じ語幹の別名の組み立て(例: `settingsButton--${…}`)の中に入らないことを、目で確かめた。
5. セレクタの中で、**括弧の外**にあるクラスが使われていないものだけを「死んだセレクタ」とした(`:not(.未使用)` のように括弧の中にあるものは、決して消さない。`:not` の中の未使用クラスは、消すと意味が変わるため)。
6. 規則のセレクタがすべて死んでいれば、規則をブロックごと消す。一部だけ死んでいれば、死んだセレクタだけを並びから外す。`@media` の中が空になるブロックは消す(該当なし)。`@keyframes`(13 個)は全部使われていた。CSS 変数(92 個)は、`var(--x)` で参照されていないものを調べ、コードにも出てこないものが 1 個だけだった。
7. 消す作業は、`postcss` の構文木で規則を外して、書き戻した(元の書式は変わらない。書き戻しだけで元と同じ文字列になることを先に確かめた)。

## 判断メモ

1. **`:not()` や `:is()` の中の未使用クラス**: 括弧の外にあるクラスだけで「死んだ」と判断した。`:not(.未使用)` は常に真になるので、セレクタごと消すと意味が変わる。`:is(.a, .未使用)` は、引数の1つだけを外した(今回は 1 か所だけ。詳細度が変わらないことを確かめた)。
2. **旧い「今日を組み立てる」の JSX の扱い**: 指示どおり JSX は消していない。そのためそのクラスの CSS も残っている(「提案」)。
3. **CSS 変数 1 個**: 指示が「迷うものは消さない」としているが、`--today-picker-font-action` は宣言が 1 か所だけで、CSS にもコードにもテストにも出てこなかったので消した。
4. **公開用スクリーンショット**: テストの実行で `docs/screenshots/` が作り直されることがあるが、この Stage の変更に含めていない(P95-05 で作り直す)。

## 提案

- 旧い「今日を組み立てる」(`legacyTodayBuilderVisible()` が常に `false`)の JSX(`App.tsx` の約 400 行)と、そこでしか使われない CSS(`todayBuilder*` など 12 個程度)の削除。見た目は変わらない。
- 同じ要素に何度も上書きしている規則の整理(例: `.projectsBand .disclosureLabel strong` のように、Phase ごとに別の場所で規則を足している箇所)。順番に依存するので、Stage を分けるのが安全。
- 今回のスクリプトのうち、計算後のスタイルの比較は、再利用できる(CSS を整理するたびに使える)。リポジトリに入れるかどうかはオーナーの判断(新しいテストの扱いになるため入れなかった)。
