## 判断メモ

1. **件数をそろえる基準の名前**。指示書は「一番長い名前『やりたいこと』の右端から 18px」だが、このテスト環境(Windows、Playwright の Chromium)の実測では、「今日の実行」の文字の右端が「やりたいこと」より約 3.1px 右にある(標準で 106.7px と 103.6px)。固定の幅ではなく、4つの名前を同じ文字で並べた見えない複製(`content` に4つの名前、高さ 0、`visibility: hidden`)で幅を決めたので、**一番幅の広い名前の右端から 18px** に件数がそろい、そのとき「やりたいこと」は 18px より約 3px 広い(約 21px)。どのフォントでも件数が重ならず、そろう。指示どおり「やりたいこと」を基準にすると、このフォントでは「今日の実行」の件数との間が 15px になる。どちらにするかはオーナーの判断。実機(Windows の Yu Gothic UI)で確認が必要。テストは「一番広い名前が 18px、「やりたいこと」が 17px 以上」を確かめる。
2. **一時停止・再開の時計の表示**。押した直後の表示は、計算した経過時間と秒単位で一致する。押したあと、自由に進んでいる間の表示は、次の1秒ごとの更新まで、最大 1秒遅れて見えることがある(interval の位相が再開の時刻とずれるため。もとからの動き)。テストは、押した直後は厳密、自由に進んだ後は 0〜1秒の遅れを許す。
3. **記録画面の「プロジェクト別(今週)」**。見出しの日付は枠の中の右端(枠の線 + 12px)にそろえたが、その下の行の「50分」は、日付より約 10px 左にある。この表の行は 4列(`20px 1fr auto auto`)のうち、3つの要素しか入れず、4列目が空のため、分数が右端から 10px(列の間隔)左に寄っている(累計の行は4つの要素があり、右端にそろう)。もとからの作りで、この Stage の範囲外のため、変えていない(指示書は、日付をその行の分数にそろえるとも、枠の余白にそろえるとも読める。枠の余白を採った)。
4. **スクリーンリーダー**。開始・一時停止を伝えていたのは、右下の通知(`aria-live="polite"` の領域)だけだった。カードや Timer の状態表示(「実行中」「一時停止」)は、ライブ領域ではない。通知をやめたので、開始・一時停止を、スクリーンリーダーが自動では読み上げなくなる。足すかどうかはオーナーの判断(指示書どおり、足していない)。
5. **上部メニューは、設定・手順書などのほかの画面でも、同じ大きさになる**(`.mainPanel` の属性を常に付けたため。以前は、メイン画面以外では標準の大きさだった)。指示書の対象は記録画面だが、上部メニューは共通なので、大きさをそろえた。
6. 上の 5 以外で、指示書に書かれていないことはしていない。

## 提案

- 「プロジェクト別(今週)」の行の4列目が空で、分数が右端から 10px 左にある件(判断メモ 3)の整理(行の列を、要素の数に合わせる)。
- 見出しの名前の幅をそろえる見えない複製は、見出しの名前を変えると(例: 英語対応)、複製の4つの名前も同じに直す必要がある。名前が1か所に定義されていないため、将来、名前を `data-` 属性などに持たせることを検討してよい。
