## 3. 直したこと

### 3.1 名前と件数の間(見出しの列)

- 原因: 名前の列が固定幅(標準 120px・大 132px・特大 144px)で、件数がその右の列(30 / 34 / 38px)に右寄せで入っていた。名前が短いほど、名前と件数の間が空いていた。
- 直し方: 4つの見出しの名前の列を `max-content`、件数の列を `max-content` にした。順番は名前・件数・説明・右端の操作のまま。`.todaySectionBar > .todayCompletionSummary` の `margin-left`(8 / 12 / 16px)は外した。表示サイズごとの列の上書き(大・特大)は、固定幅がなくなったので不要になり削除した。
- 測定(1080×680、`createFullTodayFixture`)。「名前の右端 → 件数の左端」は、名前の要素の右端から件数の要素の左端まで(名前には P8.9 の `left: -4px` の見た目の補正が付いているので、その分も含む)。

| 表示サイズ | 変更前(今日の3件 / 次の一手 / やりたいこと / 今日の実行) | 変更後(4つとも) |
| --- | --- | --- |
| 標準 | 26 / 44.3 / 33.4 / 30.3 px | 18px |
| 大 | 30 / 52.6 / 40.2 / 36.6 px | 18px |
| 特大 | 34 / 64.8 / 51.6 / 47.8 px | 18px |

- 18px の内訳は、列の間隔 8px + 開閉ボタンの右の余白 6px + 名前の見た目の補正 4px。指示書の目安(12〜18px)の上端。
- 「件数(または「n / n 完了」)の右端 → 説明の左端」は 8px で、変更前と同じ。今日の3件が 0件のとき(「0件」だけ)は、変更前は 16px(空の列を挟んでいた)だったのが 8px になった(「n / n 完了」と同じ並び。指示書の「0件のときも同じ」に合わせた)。
- 見出しバーの高さ、hover の背景、フォーカスの輪の位置、開閉の動作、右端の操作(「＋ プロジェクト」「…」「自動」)の位置は変えていない。高さは変更前と同じ(標準 48 / 48 / 48 / 44px、大 53px、特大 57px)。
- 幅が狭いときに説明を隠す決まり(900px・820px 以下)は変えていない。

### 3.3 勝利条件が未入力のとき

- 未入力の判定は、候補チップを出している条件(`victoryText` が空)と同じ。そのとき `.victoryBar--empty` を付ける。
- 光らせる条件は、`:not(.victoryBar--empty):hover` と `:not(.victoryBar--empty):has(.victoryInput:focus)` だけにした(未入力では枠・背景・1px の反応を付けない)。
- A(マウスを乗せると文字が黄色くなる): 未入力のときは `.victoryTextButton--empty:hover` で補足色のままにした。
- B(起動時の自動フォーカス): 自動フォーカスは残した(そのまま Enter で入力を始められる)。自動で入れるときだけボタンに `data-auto-focus` を付け、`.victoryTextButton[data-auto-focus]:focus-visible` で黄色い輪を消す。印は、ボタンの `blur` か `keydown` で外す。外れたあとは今までどおり輪が出る(Tab で移ってきたときも出る)。
  - 方法の選び方: `focus({ focusVisible: false })` は WebView2 側での効き方を実機以外で確かめられないので、どの環境でも同じに動くクラス(属性)の方法にした。
- 入力して1文字以上になると `.victoryBar--empty` が外れ、入力済みと同じ反応(編集中も枠が強いまま)に戻る。1文字消して空にすると、また光らない状態に戻る。
- 入力済み・達成済みのときのマウスの反応は変えていない(P9-13 のテストがそのまま通る)。

### 3.4 見出しバーの枠

- P9-07 で見出しバーの枠を透明にしていた規則(`.todaySectionBar, .disclosureHeader { border-color: transparent }` と、hover / フォーカス中の透明の指定)を外した。元の規則が戻り、枠は `1px solid var(--line)`、hover は `var(--muted)`、背景は今と同じ(`--control-neutral-hover-bg`)になった。
- P9-07 のほかの変更(セクションの上線、上部メニューの外枠、カード内のテキストボタン)は戻していない。枠の太さは P9-07 でも残してあったので、高さ・配置は変わらない。

### 3.5 二重の四角

十字キー・Tab でフォーカスが移るすべての要素(Main、サイドバー、上部メニュー、Timer。Main 画面にある 80 個)を、1つずつフォーカスして、「自分の輪」と「祖先の輪・枠・背景の変化」が同時に出るかを調べた(調べたスクリプトは報告に添付していない作業用のもの)。

| 場所 | 状態 | 対応 |
| --- | --- | --- |
| 4つの見出しバーの開閉ボタン(今日の3件、次の一手、やりたいこと、今日の実行) | バーの輪 + 開閉ボタンの輪の二重 | 開閉ボタン自身の輪を消した(`.todaySectionDisclosure:focus-visible`、`.disclosureHeader .disclosure:focus-visible` の `outline: none`)。バー全体の輪だけが出る |
| 見出しの中の別のボタン(「＋ プロジェクト」「＋ やりたいこと」「…」) | そのボタンの輪だけ(バーには出ない) | 変更なし(テストで確かめた) |
| 勝利条件(本文・チェックボックス・候補チップ) | 枠が金色に強まる + 内側の黄色い輪の二重 | 枠を光らせる条件から `:focus-within` を外した(3.3)。内側の輪だけが出る。編集中(入力欄は輪が出ない)だけ枠が強い |
| 今日の3件・次の一手のカード(`:focus-within` の枠の色 + 中のボタンの黄色い輪) | 色が違い二重の四角には見えない | 指示どおり変更なし |

- 上記以外に、二重になる場所は見つからなかった(サイドバー、上部メニュー、Timer は祖先に変化なし)。
- 「今日やるものを選ぶ」画面の見出し(`.todayBuilderHeader`)は `.disclosureHeader` と `.disclosure` を使っているので、同じ規則が当たる。この画面は、上の調べには含めておらず、画面でも確かめていない(Main の見出しと同じ規則であることだけを確認した)。
