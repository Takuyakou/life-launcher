## 5. 並び順(条件0の判定)

`project_in_today3(project, today, date)`:

- `today.date == date`(`load_do_now_candidates` が既存の `today_date` で求めた日付。新しい日付は作っていない)
- 項目が未完了、`source_key`(前後の空白除く)が `project:<projectId>`
- `source_generation_id == next_step.generation_id`(Rust の `Option` の等値。両方なしは一致、片方だけは不一致。TypeScript の `sameSourceGeneration` と同じ)

並び替えは「条件0(ある方が先)→ 今週の重点 → 今日の実行なし → 最後の実行が古い → 手動順」。理由コードは、条件0の候補を `today3`、それ以外は従来の `noToday` / `manualOrder` / `oldestSession`。同順位の判定(`manualOrder` か `oldestSession` か)には条件0の一致も含める。

## 6. テスト

### Rust(`sessions.rs`、6件追加、全体で 130 件通過)

- 今日の3件に対応する候補が、今週の重点でなくても、今日実行済みでも先頭に来る。理由が `today3`。他の候補も残る(filter でない)
- 先頭に来ない: 完了済み、世代が違う、項目だけに世代 ID がある、次の一手だけに世代 ID がある、手動項目、やりたいこと由来
- 両方の世代 ID がない旧形式は先頭に来る
- `today.date` が今日でない場合は無視される
- 対応する候補が複数のとき、その中は今の順(今週の重点が先)のまま
- 今日の3件が0件、または全件完了の日は、並びも理由も今と同じ

### Playwright(`phase9-do-now-today3.spec.ts`、8件)

モックの `setDoNowCandidates` で候補の応答を差し替えた。Rust の並び替えは書き写していない。

- `today3` の候補で推薦理由が「今日の3件に入っている一手です」。「他の一手」に切り替えると従来の文。14日以上空いた場合の短時間案内が最優先
- 今日の3件を並べ替え・外す・追加・完了したとき、それぞれ `load_do_now_candidates` が再度呼ばれる
- 候補が更新されても、今やる一手だけの完了の保持(「次の一手を見る」まで)が崩れない
- 「他の一手」で選んだプロジェクト X が、並び順の変化で位置が変わる応答(最後・先頭・短い一覧)に差し替わっても、今やる一手は X のまま
- X が消える応答では先頭に戻り、あとで候補に戻っても先頭のまま
- 「他の一手」の巡回は、選んだプロジェクトの次へ進み、最後の次は先頭へ戻る

## 9. 判断メモ

- **「他の一手」の選択の扱い(挙動)**: 選んだ候補は「プロジェクト ID」で保持する(オーナー指示。当初は番号で保持していたが、今日の3件の変更で並び順が変わると、利用者が選んだものとは別のプロジェクトに黙って切り替わるため)。
  - 候補が更新されたとき、選んでいたプロジェクトが候補に残っていれば、その新しい位置に合わせて同じプロジェクトを表示し続ける(先頭に来た場合は先頭の候補として表示する)。
  - 残っていなければ先頭に戻り、選択は解除される(あとで候補に戻っても選び直されない)。
  - 番号が範囲外になったときに最後の候補へ詰める処理は、この方式に置き換えた(番号の state 自体を無くし、表示位置は毎回 ID から求める)。
  - 「他の一手」を選んでいない間は先頭の候補を表示し、並び順の変化に従う(今日の3件に採用すると、今やる一手がそれに変わる)。
- **候補の取り込みの一本化**: 候補を読み込む経路が2つあった(`refreshDoNow` と、実行記録を読み直す `refreshSessions`)。後者は何も調整していなかったため、両方を `applyDoNowResponse` に通すようにした。
- **更新関数の純粋さ**: 選択の解除は、現在の選択と応答だけから決まる更新関数で行う(React の開発モードは更新関数を2回呼ぶ。可変な ref を中で読むと結果が食い違うため、ref を使わない)。
- **更新されない経路**: 今日の3件を追加・外す・完了・並べ替えると、いずれも `config` が変わり、`config` の変更で `refreshDoNow` が呼ばれる(既存)。更新されない経路は見つからず、新たな `refreshDoNow` 呼び出しは足していない。
- **今日の3件の完了表示の優先、今やる一手だけの完了の保持**: 変更していない(テストで確認)。
- **今日やるものを選ぶ画面の候補**: 変更していない(今やる一手の候補選びだけ)。
