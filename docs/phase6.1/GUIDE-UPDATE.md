# Guide / 使い方 更新計画

## 1. 対象

**Windowsアプリ内のGuide / 使い方・運用ガイド**と、実装に対応する
`docs/spec/current-spec.md`。P61-00で入口・文書・component・翻訳の所在を確認する。
Web Demoの説明、Zenn原稿、公開済みv1.0.0のREADMEを、未リリースv1.1の仕様へ書き換えない。

本計画の文案は下書き。P61-01/02の実際のUI・button名・テストへ合わせて完成させる。
報告書にはGuideの最新本文は載っていないため、現在のGuideがどうなっているかを断定しない。

## 2. Guideの入口に置きたい説明

```text
迷ったら「今やる一手」から始められます。
自分で選ぶときは、候補の「今日へ」を押して「今日の3件」に入れます。
やりたいことの登録は「やりたいこと」、
続けて取り組むことの次回の内容は「次の一手」で設定します。
```

ここでToday3とDo Nowの推薦関係を断定しない。
Do Nowは現行の候補条件をコードで確認し、必要な情報だけ別項へ書く。

## 3. 推奨構成

### A. まず使う

1. 単発でやりたいことを「やりたいこと」の＋追加から登録する。
2. 登録した行の「今日へ」で今日の3件に入れる。
3. カードから短時間または通常タイマーで開始する。

全手順でProject登録を要求しない。架空例は読書、片付けなど一般的なもの。
「これをすれば必ず習慣化する」等の効果を保証しない。

### B. 続けて取り組むこと

- 次の一手の登録フォームでは、取り組み（Project）と次回やる内容を設定する。
- 継続活動の例: `読書 / 第4章の続きから読む`。
- 今週の重点・任意の長期目標・手順書・起動actionは実装どおりの任意設定。
- 新規Project作成と既存NextStep更新の違いを、実画面の名前で説明する。

### C. 候補が増えたとき

```text
「今日を組み立てる」では、
「次の一手」と「やりたいこと」の候補をまとめて見られます。
今日取り組むものだけ「今日へ」で選んでください。
ここで新しい項目を登録する必要はありません。
```

候補は5件ずつ表示。6件以上ある場合はページを切り替える。
元の内容を変えたいときはNextStep/Wishlist側の編集へ。
Builder側で「削除してください」「＋追加」「勝利条件に送る」と説明しない。

### D. 今日の3件

```text
一度に並べるのは3件までです。1日合計3件という意味ではありません。
タイマーが満了し、終了を確定すると、その項目に完了の印が付きます。
途中で終了した場合は、実行記録と項目の完了を区別します。
```

`満了後に押すbutton名`、記録の1分条件、継続時の挙動を現物と照合する。
単に「Timerが0になればチェック」としない。手動checkbox操作を案内しない。
タイマー完了は記録上の完了であり、「タスクの成果達成をアプリが検証する」とは書かない。

### E. まだ取り組みたいとき

```text
3件を終えると「次の3件を選ぶ」が表示されます。
まだ取り組みたいときだけ押して、候補から次の1〜3件を選べます。
それまでの実行記録は残ります。自動で次の項目が入ることはありません。
```

1/2件だけ完了した場合のCTA条件は現行仕様を変えず正確に記す。
「次batch」など内部語を見出しに使わない。

### F. 迷ったときの「今やる一手」

現行の候補条件、固定ルール、理由表示、別の候補、短時間/通常開始を説明する。
報告書で推薦アルゴリズムは変更されたと確認できていない。
`必ずToday3から選ぶ`等と書かず、P61-00のコード照合結果を採用する。

### G. 操作の補足

- 編集/削除は元項目の右クリック（対応箇所）。
- キーボードのcontext menuはShift+F10 / Menu key。
- 辞書の矢印キーとカテゴリ移動、検索欄では矢印を奪わないこと。
- Explorer表示はfile選択/folderを開く。URL等は対象外。

既存Guideに正しい説明があれば保持し、今回関係ない記述は書き直さない。

## 4. 小さい画面内説明も合わせる

| 場所 | 文案 |
|---|---|
| NextStep | 各プロジェクトで、次にやること |
| Wishlist | あとでやりたいことを置いておく |
| Builder | 次の一手・やりたいことから、今日やるものを選ぶ |
| Today3 | 今日やると決めたものを、一度に3件まで |
| Do Now | 迷ったら、まずこれ |

これらも確定前に実装・画面密度を確認する。説明を常時何行も増やさない。
初回強制ツアー、説明を閉じるまで操作不可、新しいオンボーディングDBは追加しない。

## 5. 旧Guideから取り除く記述

現物にある場合だけ修正する:

- Today3/Builderの＋追加から新規入力する説明。
- Builderで勝利条件等をプルダウン選択する説明。
- Builderから項目を削除/非表示にする説明。
- Wishlistの行内入力と×で閉じる説明。
- NextStep一覧からタイマーを開始する古い説明。
- チェックを手動で付ける説明。
- 「1日3件まで」と「同時3件」の混同。
- 「0秒到達だけで完了」と「満了後終了確定」の混同。
- 「今日へ」で元データが消えるという古い説明。

## 6. 互換性の案内

旧Builderで隠した候補も、新しい一覧では元の項目があれば表示される。
必要ならGuideの変更点欄へ1文だけ記載し、ユーザーの削除済みsourceを復活させたように書かない。
候補の見え方が変わるだけで、Project/Wishlist/実行記録を消さない。

## 7. Guide検証

説明中の機能断定ごとに、対象UI、ソース、browser/Rust test、状態条件を対応づける。
全体を雑な単語検索だけで合格にしない。

例:

| Guideの説明 | 実装の証拠 | 自動確認 |
|---|---|---|
| やりたいことはmodal登録 | 現物component/handler | ＋追加→dialog→保存 |
| Builderは既存候補 | selector/loader | 元項目登録→候補表示、独立保存なし |
| 今日へはToday3へ採用 | 既存採用handler | 3経路、source保持、重複・上限 |
| 満了後終了確定で完了 | Timer終了handler | 満了のみ/確定/手動停止を分離 |
| 次の3件 | 現行batch transition | history保持と案内先確認 |

Guide本文に開発用の証拠表を載せない。証拠表はStage報告内にまとめる。
Guide画面も匿名データで撮影し、860px等の狭幅、スクロール、見出し/リンク、
キーボード/フォーカスの回帰を確認する。
