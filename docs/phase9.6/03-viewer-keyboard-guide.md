## A. 手順書ビューアーの十字キー操作

### 決まりの反映

| 場面 | 実装 |
| --- | --- |
| 開いたとき・窓が前に出たとき | どこにもフォーカスが無ければ、一覧の開いているファイルの行(無ければ先頭の行)へ置く。行がまだ読めていないときは、行ができた時点で置く(`focusToken` の合図 + 行の出現待ち) |
| 一覧 | 今までどおり(↑↓移動・→←でフォルダー開閉/親へ・Enter・Home/End)。↑↓ではファイルを開かない |
| 一覧 → 本文 | ファイルの行で → を押すと本文へ移る。開いていなければ先に開き、**読み終わってから**本文へ移る(読み込み中は本文の欄が作り直されてフォーカスが外れるため) |
| 本文 | ↑↓40px、PageUp/PageDown 1画面(90%)、Home/End 先頭と最後、← で一覧の開いているファイルの行へ戻る。`tabIndex={0}`・`aria-label="手順書本文"` |
| HTML | `iframe` の中の文書(`scrollingElement`)をスクロールする。`sandbox` は変えない |
| 検索欄 | 空のとき ↓ で一覧へ(開いているファイルの行、無ければ先頭)。入力中は今までどおり検索結果の選択 |
| 一覧の先頭の行 | ↑ で検索欄へ戻る |
| ヘッダーのボタン | ←→ で移動(窓のボタンを含む、左から右)。端では止まる |
| 一覧の幅の仕切り | 今までどおり |
| 編集中 | `textarea` の中では十字キーは文字の編集(変えない) |
| フォーカスの輪 | 本文の欄に `outline: 2px solid var(--accent)`(`outline-offset: -2px`)。1つだけ |

- マウス操作、ドラッグでの並べ替え、右クリックのメニューは変えていない。
- 設定画面の十字キー操作(P95-04)には触れていない。

## 判断メモ

- 「開いた直後に一覧へフォーカス」は、ビューアーが合図(`focusToken`)を出し、一覧側が**行ができた時点で**置く形にした。フォルダーの読み込みが非同期なので、開いた瞬間に行が無いことがあるため。
- 一覧から → で本文へ移るとき、開く場合は読み込み中に本文の欄が作り直されてフォーカスが外れる。そこで「開く場合は読み終わってから移す」ようにした(実装中にテストで発見)。
- 本文のスクロールは、HTML のときだけ `iframe` の文書を対象にする。`sandbox` は変えていない。
- 「使い方」の「閉じる」は、新しい CSS を足さず、今ある赤いボタンの class をそのまま使った(見た目が必ず一致する)。

## 提案

- **HTMLの編集**: 仕様 §17.2 は HTML の編集を「読み取り専用」としているが、実装は「ファイルが読み取り専用でなければ編集できる」(編集ボタンは `readOnly` だけを見る)。仕様と動きが食い違うため、文章も動きも変えずここに書く。どちらに合わせるか決めてほしい(文章は「HTMLは見るだけです」のまま)。
- ほかのダイアログで「閉じる」だけが緑のものは見つからなかった(閉じるは × のアイコン、または保存/キャンセルの組)。
- 一覧の行にフォーカスが入るようになったため、ビューアーを開いた直後に Tab を押すと一覧の次の要素へ移る。今までの「Tab で一覧へ入る」流れと実質同じだが、実機で違和感がないか見てほしい。
