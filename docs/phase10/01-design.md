## 2. 土台(段 P10-01)

### 2.1 フォント(D6)

- 今:`src/styles.css:5` の `font-family: "Segoe UI", "Yu Gothic UI", "Meiryo", system-ui, sans-serif`(Windows の字)。数字用の等幅は `"Cascadia Mono", "Consolas", monospace`(`styles.css:1959` ほか)。
- 後:`font-family: 'Inter', 'Noto Sans JP', 'Yu Gothic UI', Meiryo, system-ui, sans-serif`。太さは 400・500・700。等幅の所は変えない。
- 同梱のしかた(第3版で決めた):npm の `@fontsource-variable/noto-sans-jp` と `@fontsource-variable/inter`(フォントのファイルとライセンスだけの包み)を依存に足し、`src/main.tsx` で読み込む。可変フォントなので太さを 1 組のファイルで持ち、字の範囲ごとに分かれたファイル(`unicode-range`)で、使う字のファイルだけ読まれる。Vite が woff2 を `dist/assets/` に入れ、ネットからは読まない。今の 800 以上の太さは 700 に、600 はそのまま(可変フォントで出せる)。CSP は `src-tauri/tauri.conf.json` の `font-src 'self' …` なので、アプリの中のファイルなら設定を変えずに読める。
- ライセンス:どちらも SIL Open Font License 1.1。`OFL.txt` をフォントと同じ場所に置き、README の「使っているもの」に書く。
- 大きさ:Noto Sans JP は全部の字を入れると 1 書体で数 MB になる。**レビューで見てほしい点 R1**(§12)。案は次の 2 つ。
  - 案 a:Google Fonts と同じく、字の範囲ごとに分けたファイル(`unicode-range`)を同梱する。使う字のファイルだけ読まれる。インストーラーの増え方と起動の速さは**見込みで、まだ測っていない**。P10-01 で、実際のファイルの合計・インストーラーの大きさの前と後・起動して最初の画面が出るまでの時間の前と後を測って報告に書く。
  - 案 b:常用漢字・かな・英数字・記号に絞った 1 ファイルにする(サブセット)。小さいが、人名などの字が Yu Gothic UI で出る(混ざる)。
  - 採る:案 a(レビューも賛成)。字が混ざらないことを優先する。同梱のしかたは上の行(fontsource の包み)。インストーラー(v1.4.3 で 3,771,887 バイト)が 15 MB を超えたら、P10-01 の中で止まってリードに聞く。
- `font-weight` が 800・850・900 の所がある(例 `styles.css:2488` の `820`、`.sectionHeading h2` の `850`)。Noto Sans JP の 700 に寄るので、見出しが今より少し細く見える。P10-01 で 800 以上を 700 にそろえ、基準画像を撮り直す。

### 2.2 色・ボタン・札の決まり

- 新しい色は足さない。今の `:root` の変数(`--good`・`--accent`・`--control-positive-*`・`--control-short-*`・`--control-danger-*` など)をそのまま使う。
- 見本で新しく出てくる札(「いまここ」「✓ 選択済み」「次の一手が未設定」)は、今の丸い札(`.timerStateBadge`・`.nextStepTodayStatus`)と同じ形にする(D21)。プロジェクトの色を使う札は `color-mix(in srgb, var(--project-color) …)` で作る(今の `.projectNextStepPlaceholder` と同じやり方)。

### 2.3 テスト

- 画面の比較の基準画像は、フォントが変わるのでほぼ全部が変わる。**P10-01 で一度に撮り直し、そのあとの段では、その段で変えた画面だけを撮り直す。**
- 字の幅が変わるので、はみ出し・折り返しのテスト(`phase81-layout-qa`・`phase9-display-size` など)が落ちる見込みがある。落ちた物は、決まりを変えずに配置で直す。

  1. 札の順が [B, A] なら B が先
  2. B が完了なら A が先
  3. 0 件なら今の並び
  4. 全部完了なら今の並び
  5. 未完了の札が手で足した札・やりたいことの札だけなら今の並び

## 14. 動き(D32〜D38。Motion)

利用者が参考にした動き(https://designbookmark.com/motion の Sidebar collapse・Command palette・File drop・Copy button・Segmented control / Tab pill・Number stepper)のうち、Life Launcher に合う 6 つを入れる(2026-11-15)。参考のサイトのコードは写さない(ライセンスが分からないため)。動きの考え方だけ使い、Motion で書く。

### 14.1 土台(P10-01 で入れる)

- 依存に `motion`(npm。MIT。React からは `motion/react`)を 1 つ足す。版は決めた物に固定する(今のリポジトリの依存の書き方に合わせ、`package-lock.json` で固定)。
- アプリの一番外側(メイン窓・辞書の窓・ミニの窓のそれぞれの根)に `<MotionConfig reducedMotion="user">` を置く。Windows で「アニメーションを表示しない」のときは、Motion の動きは全部すぐ終わりの形になる。今のアプリの `prefers-reduced-motion` の決まり(調べ A-5)と同じ考え。
- ばねの値は 1 か所(例 `src/motion.ts`)に名前を付けてまとめる。例:`springSnappy`(帯・面が追いかける。`{ type: "spring", visualDuration: 0.25, bounce: 0.15 }`)、`springLayout`(高さの開け閉め。`{ type: "spring", visualDuration: 0.3, bounce: 0 }`)。値は P10-01 でテスト用の起動で見て決め、報告に書く。
- CSP:Motion は要素の `style` を書き換えて動かす。今の CSP は `style-src … 'unsafe-inline'` なので変えなくてよい(`src-tauri/tauri.conf.json:29`)。
- 大きさ:足した後の `dist/` の大きさを、前(調べ C-4:1,035,336 バイト)と比べて報告に書く。
- 今の CSS の動き(始めるボタンの浮き方と下の線、札のホバー、トースト、窓の上端の線など)は **Motion に置き換えない。** 利用者が気に入っている物なので、CSS のまま残す(D1・D2・D17・D18)。Motion を使うのは D33〜D38 の所だけ。
- テスト:Playwright は `reducedMotion: "reduce"` で回している(`playwright.config.ts:22`)ので、今の画像の比較は動きに左右されない。動きそのものは、`page.emulateMedia({ reducedMotion: "no-preference" })` にした働きのテストで、終わりの形(位置・高さ・文字)だけを `expect.poll` で確かめる(途中の形は確かめない)。
