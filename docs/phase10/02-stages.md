# Phase 10 段の分け方(第3版)

## 決まり

- 1 段 = 1 ブランチ = 1 PR。main に入れる(マージする)のは利用者。ワーカーは自分のブランチにだけ push する。
- **始める条件:下の表の「前提」の段が、全部 main に入っていること。** 番号の順ではない。前提がそろっていれば、番号が後の段を先に始めてよい(例:P10-04 は P10-00 の後なら P10-01 と同じ時期に進めてよい)。始める前に main を最新にする。
- どの段も、終わりに次を通す:
  - `npm.cmd run public:check`
  - `npm.cmd run lint`
  - `npm.cmd run build`(型の確かめを含む)
  - その段の spec だけを `npx.cmd playwright test <spec>` で(足した・書き換えた・変えた部品の目印を使っている spec)。**全部のテスト(FULL = `npm.cmd run test:visual`)は Phase 10 で 2 回だけ:P10-01 の終わりと P10-13 の終わり**(回しすぎないため。2026-11-15 利用者の指示)
  - `cargo test`(`src-tauri` で。Rust を変えた段)
- 見た目の基準画像は P10-01 で一度に撮り直す。そのあとは、その段で変えた画面だけ撮り直す(撮り直した画像の一覧を報告に書く)。
- 実機の確認はテスト用の起動(`scripts/start-test-profile.ps1`)だけ。ふだんの Life Launcher は閉じない。利用者のデータ(`%APPDATA%`)は読まない・変えない。
- CI を待つのはリリースの時の 1 回だけ。
- 決まりに無い所で迷ったら、自分で決めずに `QUESTION` を書いて止まる。とくに保存・やり直し・データの形に関わる所。

## 並べ方の考え

- P10-01 を先にするのは、フォントで字の幅が変わり、ほぼ全部の基準画像が変わるため。あとの段で、フォントの差と配置の差が混ざらないようにする。
- P10-00b は今の不具合なので、画面の作り直しと分けて先に入れる。やりたいことと次の一手を結ぶ値(`sourceWishlistId`)を使う段(P10-06・P10-09)の前提にする。
- 動き(Motion)は、P10-01 で土台だけを入れ、それぞれの部品を作り直す段で一緒に付ける。動きだけの段は作らない。
- P10-04(Rust)は画面と分ける。今やる一手の並びが変わったとき、原因が並びの決まりか画面かを分けて見られるようにする。
- 検索の欄は、働く検索の窓と同じ段(P10-03)で入れる。押しても何もしない欄を main に入れない。
- 保存に関わる段(P10-09・P10-10・P10-11)は、指示書に 01-design の決まり(確かめ・連打・失敗)をそのまま写す。ワーカーが自分で決めない。

## 各段の指示書に必ず書く物

- ブランチ名、元にする main のコミット、前提の段がマージ済みであること
- 変えるファイルと、変えてはいけないファイル
- 決まりを変えるテストは、spec の名前・テスト名・前の期待・後の期待
- 新しく足すテストの名前と、何を確かめるか
- 報告(`done/P10-xx.md`)の形:branch / commit / pushed / result / checks、撮り直した基準画像の一覧、迷った所
