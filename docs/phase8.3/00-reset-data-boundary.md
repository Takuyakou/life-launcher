# P83-00 Software Reset Data Boundary

## Boundary rule

Software reset returns **Life Launcher-owned state and registrations** to `initial_config()` while preserving user-owned external content and recovery archives. A stored path/URL has two layers:

- the Life Launcher registration is app-owned and reset;
- the file, folder, app, URL, or instruction content at that target is externally owned and is never deleted or moved.

The authoritative fresh config is `initial_config` in `src-tauri/src/models.rs:807`, using defaults from `default_settings` at line 786. It produces schema v3, empty Quick/Dictionary registration, projects, Today, Wishlist, and completion history; timer defaults 25/5, day start 4, autostart off, mini mode on, and no backup/instruction folders.

## App-owned disk state

The application uses a custom runtime root `%APPDATA%\life-launcher` (`config_dir_path`, `src-tauri/src/commands/config.rs:802`).

| Storage | Owner/content | Reset? | Required fresh result | Notes/risk |
| --- | --- | --- | --- | --- |
| `%APPDATA%\life-launcher\config.json` | Entire `AppConfig` | Yes | Serialized `initial_config()` | Must use schema v3 validation and atomic replacement. |
| `config.json` -> `groups`, `buttons` | Quick groups and app/file/folder/URL registrations | Yes | Empty | External targets referenced by actions remain untouched. |
| `config.json` -> `overlayPages`, `dictionaryOrder` | Dictionary pages/order | Yes | Empty arrays | App-owned registrations only. |
| `config.json` -> `projects` | Project, NextStep, execution setup, instruction references | Yes | Empty | Referenced instructions and launcher targets remain external. |
| `config.json` -> `today` | Date, victory, Today3, candidate exclusions, mutation tokens | Yes | Current reset date, empty victory/items/exclusions/tokens | Date must be generated once using default day-start rules. |
| `config.json` -> `inbox` | Wishlist | Yes | Empty | Includes app registration and execution references only. |
| `config.json` -> `sourceCompletions` | Project/NextStep/Wishlist completion history | Yes | Empty | This is separate from sessions and is app-owned history. |
| `config.json` -> `settings` | Timer/day/always-on-top/autostart/mini/shortcuts/backup/instruction registration | Yes | `default_settings()` | Resetting backup-folder registration must not delete that folder or its archives. |
| `%APPDATA%\life-launcher\sessions.jsonl` | Timer and manual execution records | Yes | Missing or empty valid file; prefer empty file | Writers are in `src-tauri/src/commands/sessions.rs:35,70,359,408`. |
| `%APPDATA%\life-launcher\notes.json` | Legacy notes/history compatibility data | Yes | `{}` | Writers are in `src-tauri/src/commands/notes.rs:42,83`. |

| `%APPDATA%\life-launcher\icons\*.png` | Derived launcher icon/favicon cache | Yes | Empty/missing `icons/`, lazily regenerated | Cache path is `src-tauri/src/commands/icons.rs:167`; no user content belongs here. |
| Runtime orphan temp files (`config.json.tmp`, `config.schema.json.tmp`, `sessions.jsonl.tmp`, `notes.json.tmp`, `*.restore.tmp`, `*.zip.tmp`) under app-owned roots | Interrupted app writes | Yes, only after snapshot/preflight | Absent | Never glob outside the exact app-owned roots. |

## Backup/recovery state: explicitly not reset

| Storage | Reset? | Reason |
| --- | --- | --- |
| `%APPDATA%\life-launcher\backups\config-*.json` | No | Exact config recovery assets created before config rewrites. |
| `%APPDATA%\life-launcher\backups\pre-session-edit-*` | No | Recovery copies created before session edit/delete. |
| `%APPDATA%\life-launcher\backups\pre-restore-*` | No | Recovery copies created before restore. |
| Future `%APPDATA%\life-launcher\backups\pre-reset-*` | No | Required rollback/recovery evidence for destructive reset. |
| User-selected `lifelauncher-backup-*.zip` files | No | User backup assets, often outside the runtime root. Existing ZIPs must survive even when the backup-folder setting is reset. |
| Other files in the user-selected backup directory | No | Entire directory is external user-owned storage. |

The reset implementation must target named runtime entries, not recursively delete `%APPDATA%\life-launcher`, because `backups/` is nested inside it.

## Browser/WebView state

Production code uses `window.localStorage`; production has no `sessionStorage` writes. The physical WebView2 profile is framework-managed, so reset should remove the known logical keys rather than recursively deleting the whole browser profile while the app is running.

| localStorage key | Content | Reset? | Source |
| --- | --- | --- | --- |
| `life-launcher.sidebar-groups` | Sidebar group collapsed state | Yes | `src/constants.ts:10`, `src/App.tsx:1108` |
| `life-launcher.weekly-review-seen` | Dismissed/seen weekly review banner key | Yes | `src/constants.ts:11`, `src/App.tsx:2686` |
| `life-launcher-mini-position` | Legacy/fallback mini position | Yes | `src/App.tsx:702,893-908` |
| `life-launcher-today-builder-order` | Today Builder candidate order | Yes | `src/App.tsx:727,7404,7874` |
| `life-launcher-instruction-always-on-top` | Instruction viewer preference | Yes | `src/instructionWindow.ts:12,31-35` |
| `life-launcher-instruction-last-opened-path` | Last external instruction path | Yes | `src/instructionWindow.ts:13,39-44` |
| `life-launcher-instruction-expanded-folders` | Instruction tree expansion state | Yes | `src/components/InstructionTree.tsx:28,101-121` |
| `life-launcher-instruction-tree-order-v1` | User-defined instruction tree display order | Yes | `src/components/InstructionTree.tsx:30,160-162,521` |
| `life-launcher.dictionary-focus-lock` | Dictionary lock preference | Yes | `src/components/DictionaryWindow.tsx:90,96,294` |

Legacy `life-launcher-today-builder-dismissed` appears only in old tests and is not read by current production code. A software reset may remove keys with the exact `life-launcher` product prefix for backward cleanup, but it must not call `localStorage.clear()` if the origin can contain unrelated keys. The implementation should keep an explicit allowlist plus reviewed legacy keys.

`sessionStorage` is used only by `tests/visual/tauriMock.ts`; no production reset work is required.

## Window state and in-memory state

| State | Storage/owner | Reset? | Hazard |
| --- | --- | --- | --- |
| Tauri window state | Resolve at runtime as `app.path().app_config_dir()?.join(app.filename())` using `tauri::Manager` and `tauri_plugin_window_state::AppHandleExt`; currently `%APPDATA%\com.takuyakou.lifelauncher\.window-state.json` on Windows | Yes | Delete and verify the exact file, then unregister plugin name `window-state` before restart so its `RunEvent::Exit` hook cannot recreate it. |
| Mini position | `config.settings.miniWindowPosition` plus localStorage fallback | Yes | Both copies must be reset together. |
| Dictionary reopen state | Module variable `dictionaryReopenState`, `src/components/DictionaryWindow.tsx:88` | Yes through process restart | Not on disk; closing/reopening only the dictionary can retain it. |
| Settings/edit drafts, Toasts, open tabs/accordions/pages | React state in `DashboardApp` | Yes through process restart | Must be frozen/discarded once reset begins. |
| Active Timer | `activeTimer` and `activeTimerRef`, `src/App.tsx:2021-2023` | Never silently cleared by reset | Running **and paused** states must reject reset before any backup/reset mutation. |
| Pending completion/early-stop/notes debounce | React refs/state | Must be drained or cancelled before reset commit | A delayed `saveNotesForDate` can recreate old `notes.json`. |
| Rust watcher/shortcut/drop state | `AppState`, `src-tauri/src/state.rs:16` | Reinitialized by restart | Watcher can emit reloads while files change; reset needs suppression/gating. |

`tauri-plugin-window-state` 2.4.1 has no public cache-clear/set API: its cache type is private and `AppHandleExt` exposes only `save_window_state` and `filename`. `save_window_state(StateFlags::empty())` still serializes the existing cache. P83-02 must snapshot/delete/verify the runtime-resolved file, require `app.remove_plugin("window-state") == true`, then immediately call `app.request_restart()`. Plugin setup in the new process loads a missing file with `unwrap_or_default()`, yielding fresh window state.

## OS integration

The Windows autostart registration created by `tauri-plugin-autostart` is app-owned. Reset must disable it because fresh settings specify `autoStart: false` (`src-tauri/src/startup.rs:233`). Global shortcut registrations are in memory and should be re-registered from fresh defaults on restart. A failure to disable autostart must fail and roll back reset rather than leave config and OS state disagreeing.

## External/user-owned data: never reset

- Registered Markdown, TXT, and HTML instruction files and every asset beside them.
- Registered instruction folders; only their paths/identities in config and instruction UI-state keys are cleared.
- Apps, EXEs, scripts, `.lnk` files, folders, ordinary files, URLs, browser data, and Recycle Bin content referenced by launcher actions.
- Chrome bookmark/profile data consulted during drop resolution.
- User-selected backup folders, existing backup ZIPs, and unrelated files in those folders.
- Installed Life Launcher binaries, installer, portable ZIP, release artifacts, WebView2 Runtime, and source checkout.
- Clipboard content and unrelated operating-system settings.

## Reset validation invariants

After reset and clean restart:

1. `load_config` returns `saveBlocked: false`, schema v3, and a value equal to `initial_config()` except for the generated current date.
2. Sessions and notes APIs return empty collections without warnings.
3. Quick, Dictionary, Project, NextStep, Wishlist, Today3, Victory, source-completion, and candidate state are empty.
4. Settings equal defaults; OS autostart is disabled and default shortcuts are applied.
5. Known localStorage keys, window positions, dismissed banner state, and accordion/group state are absent/default.
6. Icon cache is empty and can be regenerated lazily.
7. External instruction/launcher targets and every pre-existing backup remain byte-for-byte untouched.
