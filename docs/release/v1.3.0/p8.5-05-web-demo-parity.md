# P8.5-05 Web Demo Parity

## Verdict

**DEFERRED — WINDOWS RELEASE NON-BLOCKING**

The Web Demo is healthy at its current feature level but is not ready for a simultaneous v1.3.0 production deployment. The Windows v1.3.0 candidate is unaffected by this decision.

Production deployment was not performed.

## Synchronized behavior already present

- Today3 maximum of three items
- stable source IDs and duplicate adoption guard
- same-text Wishlist identity
- removing Today adoption without deleting the source
- Timer and early-completion simulation
- Project color labels and Today card accents
- localStorage validation and legacy Today source normalization
- keyboard focus and reduced-motion support
- local-only static SPA without analytics or external application APIs

## Missing v1.3 parity

- The permanent `今日を組み立てる` Builder remains; the frozen Today Picker contract is absent.
- Selected candidates remain in the Builder instead of disappearing from the source list.
- Project creation and direct NextStep setup flows are absent.
- Wishlist items do not belong to or group under Projects.
- NextStep/Wishlist source locks and `✓ 今日の3件` status are absent.
- Do Now still says `別の候補`; its card accent remains fixed green instead of following the candidate Project.
- Required hover/focus/pressed/disabled, Do Now A/B color, Today Picker, and responsive visual matrices are incomplete.
- A versioned migration for Project-backed Wishlist data does not yet exist.

These gaps change the Demo's information model and primary interaction, so they were not disguised as a small release-audit patch.

## Deployment decision

- Windows v1.3.0: may proceed to final release decision.
- Existing Web Demo production revision: may remain online.
- Web Demo v1.3.0 sync: must not deploy from this audit branch.
- Next step: implement the follow-up list in the Web repository report, rerun all gates, and obtain separate deployment approval.
